## 何をしているのか

**SFT（Supervised Fine-Tuning，教師ありファインチューニング）** は，
「この入力にはこう答えてほしい」という組を大量に見せて，モデルの重みを
その方向へ動かす作業である．

本研究では次の組を1000件見せる．

```
入力（プロンプト）: ルールの説明 + チャレンジ C = [5, 4, 6, 1, ..., 4]
出力（教師）      : {
                      "answer": 8
                    }
```

鍵 $\sigma$ はプロンプトに**書かれていない**（Stage 2 = ルールのみ開示）．
モデルは1000件の入出力から鍵を推測し，重みの中に覚えるしかない．

なお損失は**出力側だけ**に掛かる（`assistant_only_loss=True`）．
プロンプトを覚えさせたいのではなく，答えを出せるようにしたいため．

## QLoRA の Q — 4bit 量子化

元のモデル Qwen2.5-3B-Instruct は約31億個の重みを持ち，通常の16bitで置くと
**約6GB**（実測 5.8GB）．研究室の GPU は 8GB しかないので，これを載せると
学習に必要な作業領域が残らない．

そこで重みを **4bit に圧縮**して載せる（16bit → 4bit なので約1/4）．
多少精度は落ちるが，元の重みは**凍結して一切更新しない**ので，
圧縮したまま使い続けられる．これが QLoRA の Q（Quantized）である．

副作用として，計算の数値精度が落ちる．後述の非決定性に効いてくる．

## QLoRA の LoRA — 低ランクの差分だけ学習する

31億個の重みを全部更新するのは，メモリ的にも時間的にも無理である．
**LoRA（Low-Rank Adaptation）** は，元の重み $W$ を凍結したまま，
**低ランクの差分**だけを学習する．

$$W_{\text{使う重み}} = \underbrace{W}_{\text{凍結・4bit}} + \underbrace{BA}_{\text{学習する}} \times \frac{\alpha}{r}$$

- $A$ は $r \times d$ の行列で，**ランダムに初期化**される
- $B$ は $d \times r$ の行列で，**ゼロで初期化**される
- $r$ は「ランク」．本研究では $r = 16$，$\alpha = 32$（$\alpha = 2r$ が慣例）

$B = 0$ なので，学習開始時は $BA = 0$，つまり**元のモデルとまったく同じ出力**から
始まる．学習が進むにつれて差分が育っていく．

$r$ が小さいほど学習するパラメータが少なくて済む．本研究の実測：

```
trainable params: 29,933,568 || all params: 3,115,872,256 || trainable%: 0.9607
```

**全体の 0.96% しか学習していない．** 保存されるアダプタも 69MB で済む
（元モデルは 5.8GB）．評価時は「元モデル＋アダプタ」を重ねて使う．

差分を入れる場所は Transformer の7種類の行列
（`q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`）の
全層である．

## 損失とは何か

損失は「正解にどれだけ高い確率を割り当てたか」を測る．**正解率ではない．**

モデルが出力すべき文字列をトークンに分けると9個になる．

```
'{\n'  ' '  ' "'  'answer'  '":'  ' '  '7'  '\n'  '}'
                                        ↑ 難しいのはここだけ
```

残り8個は定型文なので簡単に覚えられる．したがって，

| 検証損失 | 意味 |
|---|---|
| $-\ln(1/10) / 9 = 0.256$ | 答えの数字が**まったく分からず**，0〜9に一様に迷っている |
| **0.19** | 鍵の値域は覚えたが，答えは当てられない（＝**学習が始まっていない**） |
| 0.0005 | 正解の数字に約99.6%の確率を割り当てている（＝**覚えた**） |

正解率で見ると「10%」も「12%」も偶然と区別できないが，**損失は下がり始めた
瞬間から連続的に動く**．そのため学習が進行中なのか一歩も動いていないのかを
見分けられる（[training_dynamics.md](training_dynamics.md)）．

**検証（validation）** はエポックの終わりごとに行われる．学習に使っていない
200問を解かせて損失を測るだけで，**重みは更新しない**．本研究では
`load_best_model_at_end` を設定していないので，モデルの選択にも使っていない．
純粋な観測である（保存されるのは常に最後のエポックの重み）．

## 乱数が効く3箇所

学習は決定的な手続きではない．乱数は次の3箇所に効く．

**1. LoRA の $A$ の初期化**

$A$ はランダム（Kaiming 一様分布）で初期化される．$B = 0$ なので出力の初期値は
変わらないが，**どの方向へ降りていくかの出発点**が変わる．

**2. 学習データの並び順**

DataLoader は毎エポック訓練データをシャッフルする．勾配降下は「見た順に少しずつ
動く」ので，同じ1000問でも順番が違えば通る経路が違う．

ただし本研究のチャレンジは最初から一様ランダムに生成されているので，
シャッフルの効果は本来小さい（データに難易度順などの構造がある場合は決定的に効く）．

**3. ドロップアウト**

後述．毎ステップ「どのユニットを落とすか」を引き直す．

これらは `key_seed`（鍵を決める）や `data_seed`（どのチャレンジを引くか）とは
**独立**である．3つのシードがそれぞれ別のものを決めている．

| シード | 決めるもの |
|---|---|
| `key_seed` | 秘密の鍵 $\sigma$ |
| `data_seed` | 学習1200問・テスト500問の中身 |
| `seed`（学習） | $A$ の初期値・並び順・ドロップアウト |

## ドロップアウト

学習中，**ニューロンの一部をランダムに 0 にして無かったことにする**手法．

```
入力 x = [0.8, 0.3, 0.5, 0.9, 0.2, ...]
         ↓ ドロップアウト率 5%
      = [0.8, 0.0, 0.5, 0.9, 0.2, ...]
                ↑ このステップでは捨てる（残りは 1/(1-0.05) 倍に拡大）
```

どれを捨てるかは毎ステップ引き直す．**評価時は無効**になり，全部使われる．

目的は**過学習の抑制**である．特定のニューロンに依存させないことで，
訓練データの細かい癖を丸暗記するのを妨げ，役割を分散させる．

本研究の設定は `lora_dropout=0.05`（5%）と控えめ．PEFT の実装では
**LoRA 経路に入る直前の入力**に適用される．

```python
result = result + lora_B(lora_A(dropout(x))) * scaling
```

元の重み $W$ の経路には掛からない．

## 再現性と GPU の非決定性

学習の乱数シードは **42 に固定されている**．ただしこれはコードに書かれておらず，
HuggingFace の既定値（`TrainingArguments.seed = 42`）がそのまま効いている．
`train_finetuning.py` にシードを指定する引数が無いため，**そもそも変えられない**．

42 という値に意味は無い．『銀河ヒッチハイク・ガイド』のジョーク由来で，
ライブラリの既定値として広く使われているだけの慣習である．

シードを固定しても，**完全には再現しない**．`full_determinism=False`（既定）
なので，GPU 側の非決定性が残る．

- GPU が並列に足し算する順序が実行ごとに変わる（`atomicAdd` の到着順）
- cuBLAS が行列積のアルゴリズムをその場で選ぶ
- bf16・4bit は精度が低いので，順序の違いが数値差として残りやすい

浮動小数点では $(a+b)+c \neq a+(b+c)$ である．1ステップでは無視できる差だが，
625ステップ積み上がると軌道が分かれうる．

**実例（2026-09-12，段階7）**: `key_seed=3`・`data_seed=1`・`seed=42` が完全に
同一の2本で，離陸が1エポックずれた．

| | ep1 | ep2 | ep3 | ep4 | ep5 | 正解率 |
|---|---|---|---|---|---|---|
| 1本目 | 0.1835 | **0.0393** | 0.0012 | 0.0006 | 0.0006 | 100.0% |
| 2本目 | 0.1917 | 0.1549 | **0.0310** | 0.0038 | 0.0024 | 99.0% |

最終的にはどちらも収束するので正解率はほぼ同じだが，**5エポックで打ち切る設計では
この1エポックのずれが結果を左右しうる**．裏を返せば，シードを実際に振れば
もっと大きくばらつくと考えられる．

## 本研究の設定一覧

| 項目 | 値 | 標準的か |
|---|---|---|
| ベースモデル | Qwen2.5-3B-Instruct | — |
| 量子化 | 4bit（QLoRA） | 標準（8GB VRAM 前提） |
| LoRA ランク $r$ / $\alpha$ | 16 / 32 | 標準（$\alpha = 2r$ が慣例） |
| `lora_dropout` | 0.05 | 標準 |
| 学習対象 | 全体の 0.96%（2,993万パラメータ） | — |
| 学習率 | 2e-4，線形減衰，**warmup なし** | lr は QLoRA 論文の標準値だが，**warmup 無しは慣習から外れる**（通常は 3〜10%） |
| optimizer | AdamW 8bit | 標準 |
| 実効バッチ | 2 × 4 = 8 | 標準（小VRAM） |
| 学習件数 / エポック | 1000 / 5（= 625ステップ） | — |
| 損失 | 答えの部分のみ | 標準 |
| 学習の乱数 | seed=42（暗黙・変更不可） | **1条件1run は研究の主張としては標準的でない**（通常は3〜5シードで平均±標準偏差） |
| 所要 | 1本あたり約100分 | — |

**手法の選択そのものは教科書どおりで，問題は無い．** 問題は用途である．
本研究は FT でモデルを作るのではなく，**FT を物差しにして関数の難しさを測る**．
測定器として使うなら，標準的なレシピでは足りない．

| モデルを作るなら | 難しさを測るなら |
|---|---|
| 1回学習すればよい | 複数シードで分布を取る |
| 固定エポックで打ち切ってよい | 収束まで回す（または収束を判定する） |
| 非決定性は許容 | `full_determinism=True` を検討する（遅くなる） |

## 用語

| 用語 | 意味 |
|---|---|
| SFT | 教師ありファインチューニング．入出力の組を見せて重みを動かす |
| QLoRA | 4bit 量子化した凍結モデル＋LoRA |
| LoRA | 低ランクの差分 $BA$ だけを学習する手法 |
| ランク $r$ | 差分行列の細さ．小さいほど学習パラメータが少ない |
| アダプタ | 学習された $A$, $B$ の組．69MB |
| エポック | 訓練データ全体を1周すること |
| ステップ | 重みを1回更新すること．本研究では 8件ごとに1回 |
| バッチ | 1ステップで見るデータの件数 |
| 勾配蓄積 | メモリ不足のため，2件ずつ4回に分けて勾配を足してから更新する仕掛け |
| 損失 | 正解にどれだけ高い確率を割り当てたかの指標．小さいほど良い |
| 検証 | 学習に使っていないデータで損失を測ること．重みは更新しない |
| 過学習 | 訓練データの癖を覚えてしまい，未知のデータで性能が落ちること |
| ドロップアウト | ニューロンをランダムに落として過学習を抑える手法 |
