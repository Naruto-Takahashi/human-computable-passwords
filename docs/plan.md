## 1. 背景と方針

### 1.1 学習による安全性評価の系譜

HCP（Blocki ら, ITCS 2017）の安全性は，研究室で4代にわたり学習器で評価されてきた
（MLP → LSTM → 埋め込み+BiLSTM → 埋め込み+CNN。[literature/lab_theses.md](literature/lab_theses.md)）。
どの世代も $`j`$ 項（入力から計算した位置を参照する項）を学習を難しくする主因とみてきた
（R7 の CNN は一部の条件で偶然水準を大きく超えたが，安定しなかった）。
ニューラルネットによる評価そのものは Murata ら（WISA 2022）として査読付きで出ている。

### 1.2 経路Cを主軸にする理由

経路C（Transformer エンコーダを1から学習）は，先行研究との差分が **self-attention だけ**である。
経路A・Bは事前学習済みの LLM を使うため，事前学習という交絡を同時に持ち込む。
経路Cは C1〜C3 で次のところまで来ている（数値は [experiment_index.md](experiment_index.md)）。

- $`N=26`$ で $`j`$ 項を解く run がある。ただし離陸するかは多くの場合**鍵**で決まる（C1。$`f_{3,1}`$・$`f_{1,3}`$ では鍵が分散の大半を説明し，$`f_{2,2}`$ では鍵と初期値の交互作用が大きい）
- 鍵の数字の偏りから学習せずに計算できる量（1変数信号 $`I_1`$）が，基準線を統制しても離陸率と相関する（C2・C2.1・C3）
- $`N \approx 100`$ でランダムな鍵が離陸しないのは，記号の数よりも鍵の分布の側の理由による（C3）
- Transformer は，$`f`$ を知る厳密ソルバーより桁違いに多い観測を要する（標本数の位置づけ）

## 2. 中心主張と研究の問い

### 2.1 中心主張（案）

> **HCP に対する勾配学習攻撃の成否は，主に個々の鍵の数字の偏りで決まり，その偏りは学習せずに
> 計算できる量で予測できる。学習攻撃が効く「弱い鍵」は，ランダムに引くと $`N`$ とともに急減し，
> 数字の個数をそろえた鍵では消える。ただし $`f`$ を知る古典的な攻撃は鍵の分布に依らず，
> 学習攻撃より桁違いに少ない観測で鍵を求める。**

この主張は 2026-10-29 に批評を受けて改訂した。改訂前の「学習による評価では安全性を判断できない」は，
否定形で仮想敵が弱く（学習の失敗を安全の証明にした先行研究は少ない），
筋書きの中で「CNN と Transformer の差」と「鍵による差」が互いを打ち消していたため取り下げた。

### 2.2 研究の問い

| | 問い | いまの証拠 | 足りないもの |
|---|---|---|---|
| **RQ1** | 学習攻撃の成否を決めるのは何か | $`f_{3,1}`$・$`f_{1,3}`$ で鍵が分散の大半を説明する（C1）。$`I_1`$ が離陸率と相関する（C2・C2.1） | 指標を事前に1つに決めた検定（多重比較） |
| **RQ2** | その鍵の性質は，介入しても効くか（因果） | 双子の鍵で分布と $`N`$ を分けた（C3） | 数字をそろえた鍵（C5）・数字の付け替え（C6） |
| **RQ3** | 先行研究で $`j`$ 項の学習が安定しなかったのは，学習器の違いか，鍵の違いか | 小川らの CNN の数値と比べただけ（鍵がそろっていない） | 同じ鍵・同じデータでの CNN（C7） |
| **RQ4** | 学習攻撃は古典的な攻撃と比べてどれだけ弱いか | 厳密ソルバー・理論の下限と比べた（ガウス消去は見積もり） | ガウス消去の実装と実測（G1） |

### 2.3 言わないこと

批評で言い過ぎと指摘された点。本文でもこの範囲に留める。

| 言わない | 代わりに言う |
|---|---|
| 関数の構造は効かない | 難しさは $`s(f)`$ の順に並ばない。関数の構造も効くが，鍵の効果が大きい |
| $`N`$ は効かない（壁は分布だけ） | 鍵の偏りが離陸の必要条件らしい。$`N`$ の効果は関数によって残る（$`f_{1,3}`$） |
| 学習器を強くしても解けない | 予算を4倍にしても動かなかった（その範囲の外は測っていない） |
| 学習攻撃は $`N^{s(f)}`$ の何倍 | $`N^{s(f)}`$ は定数と対数を落とした桁の目安。比べられるのは復元に要した件数 |
| 鍵の数字をそろえれば HCP は安全になる | 学習攻撃に限った対策。ガウス消去には効かず，鍵の空間も減る |
| 2次以上の信号が効く | 既存の鍵では1次と分けられない（C4）。理論との対応は「向き」として考察で述べる |

## 3. 足りない証拠と実験計画

**どれも GPU を使わない**（経路Cは CPU 並列で回している）。回す前に設計を

| 優先 | 名前 | 問い | 設計の要点 | 状態 |
|---|---|---|---|---|
| 1 | **C5** | 数字の個数をそろえた鍵では離陸しないか（RQ2） | $`N=30`$ で各数字3個ずつの鍵（$`k_2+1`$ 次未満の信号が厳密に0）と，ランダムな鍵・偏りの大きい鍵を比べる | 設計済み（[experiment_index.md](experiment_index.md)） |
| 2 | **C6** | エントロピーを固定して $`I_1`$ だけを動かしても効くか（RQ2） | 数字の付け替え $`\sigma'=\pi\circ\sigma`$ はヒストグラムの形を保ち，$`I_1`$ だけを動かす。$`f_{1,3}`$ だけ（$`f_{2,2}`$ は基準線をそろえた組が作れない） | 設計済み（[experiment_index.md](experiment_index.md)） |
| 3 | **C7** | 同じ鍵で CNN は $`j`$ 項を越えるか（RQ3） | C2 の鍵・データで小川らの CNN を再現し，経路Cと離陸率を比べる | 未設計 |

| 5 | **R1** | 既存データで，事前に決めた1つの指標が効くか（RQ1） | C2・C2.1・C3① を合わせ，鍵を変量効果とするロジスティック回帰 | 未設計（データはある） |

## 4. 測り方の約束

経路Bで実際に失敗して得た規則（[experiment_index.md](experiment_index.md) の
「これまでに確定した方法論上の規則」）をそのまま使う。経路Cで特に効くもの。

- **離陸率で報告する。** 離陸は検証正解率の最大が 0.5 を超えた run。平均±標準偏差は混合比を報告しているにすぎない
- **鍵ごとの最頻値基準線と比べる。** 相関分析でも基準線を統制する（C2 の撤回）
- **鍵と初期値を分けて引く。** 解析の単位は鍵
- **比較相手は実験内に置く。** スレッド数が違うだけで同じ seed の結果が入れ替わる（C3）
- **指標は結果を見る前に決め，予測変数どうしの共線性も先に見る**（C4）

## 6. リスクと対処

| リスク | 対処 |
|---|---|
| C5 でランダムな鍵も離陸しない（床） | 偏りの大きい鍵を陽性対照として同じ実験に置く。それも離陸しなければ $`N=30`$ が既に床で，$`N=26`$ で組み直す |
| C5・C6 で予測と違う結果になる | どちらに転んでも書ける形で予測と解釈を先に書く。「鍵の偏りが効く」が崩れたら，中心主張を RQ3・RQ4 中心に組み替える |
| C7 で CNN も同じ鍵で離陸する | 「$`j`$ 項の学習が安定しなかったのは鍵の違い」となり，中心主張（鍵が決める）がむしろ強まる。学習器の差の主張は取り下げる |
| G1 の実装が重い | $`f_{1,3}`$ だけに絞る。それも間に合わなければ見積もりのまま限界に明記する |
| 計算時間 | 1 run は CPU で約10〜35分（並列数による）。各実験の run 数 × 所要時間を設計時に計算する |

## 7. 凍結した経路A・Bから引き継ぐもの

| 経路 | 凍結の理由 | 引き継ぐもの |
|---|---|---|
| 経路B（LLM の微調整） | 事前学習の交絡を持ち込み，学習器の差を切り分けられない。主張は撤回・保留が多い | 測定系の交絡の発見と方法論上の規則（第4章の骨格） |
