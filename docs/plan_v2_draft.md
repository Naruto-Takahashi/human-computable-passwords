# 研究計画 v2（ドラフト）：LLM による HCP 鍵逆推定の相転移境界 — 情報理論的限界との対比

作成日: 2026-07-12
位置づけ: `plan.md`（v1）の全面改訂ドラフト．FT実験の行き詰まり（PoT鍵リーク，Pureモード崩壊，VRAM制約）を受け，研究の主軸をプロンプティング（in-context推論）による相転移測定に移し，情報理論的限界・ソルバー限界との対比を新たな柱として追加する．

---

## 0. 方向転換の要旨

| | v1（従来計画） | v2（本計画） |
|---|---|---|
| 主軸 | Few-shot vs QLoRA-FT の比較 | **in-context鍵逆推定の相転移境界の測定** |
| 基準線 | CNN/Bi-LSTM（数万件の教師あり学習） | **情報理論的一意特定限界 N\*** ＋ **厳密ソルバー**（＋既存のCNN結果は参考値として残す） |
| FTの扱い | 中心的RQ（RQ3） | **補助実験に降格**．過学習テストでパイプラインの健全性だけ決着させ，凍結 |
| PoT | FTの教師形式 | **評価時の回答形式**として再利用（モデルに「仮説の鍵＋ルール」をコードで出力させ，held-outペアで採点） |

### なぜこの転換か

1. **FT-PoTは鍵リークで原理的に成立しない**（発見済み）．リークしない教師設計は「鍵の出力を強制しない ≠ 鍵を与えてよい」の原則下では見つかっていない．
2. **FT-Pureのモード崩壊は起こるべくして起こる**．教師信号が answer 1トークン（≈3.3 bit/件）しかなく，26要素の鍵（≈86 bit）を焼き付けるには勾配信号が貧弱すぎる．これは plan.md §1.4 で理論的に予見していた「勾配の到達範囲」問題そのもの．仮にラベルマスク等のバグを潰しても，本質的困難が残る公算が大きい．
3. **VRAM 8GBではFTのモデル規模スキャンが物理的に不可能**（3B/4bitが上限）．一方プロンプティングは Ollama（7B/14B）＋商用API（規模スキャンの上限側）で自由に振れる．
4. **モンテカルロで判明した事実が研究の核になる**: n_shot=10 では鍵は情報理論的に一意特定不可能（候補 10^16〜17 通り残存）．一意特定には N≈26〜50 が必要．つまり従来の「LLMは逆推定できない」という観測の一部は**能力以前に情報不足**だった．
   → 「**情報理論的に解ける領域（N ≥ N\*）で，LLMはどこまで解けるか**」という問いに再定式化できる．このギャップ（N\*_LLM / N\*_info）こそが「LLMの帰納推論の欠損」の定量値であり，本研究の主要な貢献になる．

## 1. 研究の問い（改訂版 RQ）

- **RQ1（情報限界 vs LLM限界）**: ルール既知・鍵未知（Stage 2）の条件で，鍵の一意特定に必要なペア数の情報理論的下限 N\*_info（モンテカルロ／ソルバーで算出）に対し，LLMが実際に鍵復元・応答予測に成功し始めるペア数 N\*_LLM はどこか．ギャップ N\*_LLM / N\*_info はどの程度か．
- **RQ2（部分開示の相転移）**: 鍵を K 要素部分開示（Stage 3）したとき，残り鍵の復元成功率は K に対してどこで「崩壊→成功」の相転移を示すか．
- **RQ3（モデル規模・推論機構）**: 相転移境界は，モデル規模（7B→14B→商用フロンティア）および推論特化機構（extended thinking / o系）でどうシフトするか．
- **RQ4（アルゴリズム難易度）**: HCPの構造的難易度（直接加算 / 間接参照 / 非線形多項式）は N\*_LLM と相転移の鋭さにどう影響するか．

仮説（レビュー指摘に対応して明示する）:
- 仮説1: N < N\*_info の領域では全モデルが偶然水準に留まる（情報不足領域の確認）．
- 仮説2: N ≥ N\*_info でも，ローカルLLMの成功率は偶然水準から有意に離れない一方，推論特化型商用モデルは有限の N\*_LLM で相転移を示す．
- 仮説3: K の増加は探索空間を指数的に縮小させるため，相転移は K に対して急峻（シャープな臨界点）になる．
- 仮説4: 間接参照（func_31）は同じ情報量でも制約伝播を困難にし，N\*_LLM を大きく押し上げる（N\*_info はほぼ不変なのに）——「情報量ではなく推論構造が律速」の証拠になる．

## 2. 実験設計

### 2.1 3本の基準線（本計画の新規性の中核）

1. **情報理論的限界 N\*_info**: モンテカルロで「N件のペアと整合する鍵候補数」の期待値を N ごとに算出し，候補数が1に落ちる N を特定する（func_22 で実施済みの手法を全ジェネレータ・全 K に拡張）．
2. **厳密ソルバー限界**: 制約伝播＋探索（必要なら Z3）で鍵を復元するソルバーを実装する．「計算機的に解ける」ことの実証であり，LLMの失敗が情報不足でも計算不能性でもなく**推論の失敗**であることを保証する統制条件．実装コストは小さい（ルール既知なので各ペアが鍵への制約式になる）．
3. **偶然水準**: 応答予測なら 1/10．鍵復元なら一致率の期待値．

### 2.2 独立変数

- **Stage**: 2（ルール開示・鍵非開示）と 3（＋鍵 K 要素開示）を主戦場とする．Stage 0/1 は少数条件のみ（「完全ブラックボックスは全滅」の確認として）．
- **ペア数 N**: 10, 20, 30, 40, 50, 75, 100（N\*_info ≈ 26〜50 を跨ぐように設定．v1 の上限100は維持）．
- **開示数 K**: 0〜26 を粗→密の2段階でスキャン（まず 0,6,13,20,26，相転移付近を細かく）．
- **難易度**: simple_add（統制条件・鍵なし）/ func_22 / func_31 / func_pow．
- **モデル**: Qwen2.5 7B/14B（Ollama），Gemini 2.5 Flash/Pro，Claude（API）．推論特化モードの有無も条件に含める．
- 各条件で複数シード（鍵・チャレンジセットを変えて ≥5 回）を回し，成功「率」として測る．

### 2.3 評価方法（PoTの再利用）

モデルには「復元した鍵の配列」＋「予測コード」を出力させ，`code_executor.py` で held-out チャレンジに対して実行して採点する：
- **鍵一致率（Key Recovery Rate）**: 26要素中の正解数．
- **held-out応答正解率**: 学習に見せていないチャレンジ n=50 での出力一致率（Rule Accuracy の定量化．0624レビューの「意味論的合致度では曖昧」指摘への回答）．
- 思考過程（reasoning trace）の定性分類：制約をどう使ったか／どこで破綻したか（第3期の考察材料）．

これは「FTのPoT」と違い鍵リークが発生しない（プロンプトに鍵を入れず，モデルの**出力**として鍵を要求するだけ）．

### 2.4 FTの扱い（凍結手順）

指導教員レビュー（0707）の優先度1・2だけを実施して決着させる：
1. 教師データ数件の目視確認（tokenizer / EOS / JSON整形 / ラベルマスク）．
2. train=20件の過学習テスト．暗記できなければパイプライン欠陥，できればタスク困難．
3. 結果がどちらでも，**「1トークン教師信号では鍵86bitを重みに書き込めない」という否定的知見**として卒論の1節（考察）にまとめ，FTは凍結する．モード崩壊の原因切り分けの過程自体が既に報告価値を持っている（0707レビューでも高評価）．

## 4. リスクと対処

- **商用APIの予算**: 重点条件（相転移近傍）に絞る設計にしてある．先に単価×件数を試算してから発注する．
- **ローカルLLMが全条件で全滅する可能性**: それ自体が仮説2の検証結果として成立する（N\*_info とソルバーの基準線があるため「情報不足」「計算不能」と切り分けた上での否定結果になり，論文として立つ）．
- **相転移が観測されない（なだらかにしか上がらない）可能性**: 「臨界点」の主張を「境界領域の幅」の測定に弱める逃げ道を持っておく．
- **長コンテキスト制約**: N=100・K開示・ルール説明でプロンプトが長くなる．トークン数を条件ごとに記録し，コンテキスト長の交絡を考察で扱う．
