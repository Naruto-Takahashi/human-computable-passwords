# 前提知識（研究全体の背景・用語・扱っている関数）

この報告書単体で内容を追えるよう，研究の枠組みと，本文中に登場する関数の定義をまとめる（過去の報告と重複するが再掲する）。

## 研究の枠組み

HCP（人間計算可能パスワード）とは，ユーザーが記憶する秘密の数表（以下「鍵」，各要素は0〜9の整数）と，暗算できる程度の簡単なアルゴリズムを使い，ランダムな入力（チャレンジ）から出力（レスポンス）を計算する認証方式である。本研究では，この「鍵をLLMがどこまで当てられるか／使いこなせるか」を測定するベンチマークとして再定義して扱っている。鍵と乱数シードから未知の問題を無限に生成できるため，事前学習データに答えが混入していないという利点がある。

研究は2つの経路で進めている：

1. 経路A（in-context推論）：LLMの重みは一切更新せず，プロンプトの中にいくつかの入出力example（チャレンジ→レスポンスの組）を見せて，その場で鍵を推論・逆算させる。

2. 経路B（ファインチューニング）：大量の入出力ペアを使い，追加学習（QLoRA）でLLMの重みに鍵とその使い方を覚え込ませる。従来の機械学習モデル（CNN）と同じ枠組みで，研究室の先行研究と直接比較できる。7月に一区切りとしたが，8月にご指示いただいた「より難しい関数の探索」を受けて再開している。今週の報告はこちらである。

## 実験の基本設定

1. **モデル**：ローカルで動かせる Qwen2.5-3B-Instruct を用い，QLoRA（4bit量子化＋LoRA）で追加学習している。

2. **Bパラダイム**：経路Bで採用している学習・評価形式。プロンプトはFew-shot例を含まない最小形式（「Input: [...] に対する Z を答えよ」のみ）とし，従来のCNNと同じ「入力→出力の直接対応のみを学習する」条件に揃えている。

3. **paradigm=pure**：教師データの形式。学習の答え（教師completion）は `{"answer": <値>}` というJSON1行のみで，計算の途中経過や鍵の値は一切含まない。損失もこの1行にしかかからず，プロンプト側（ルールの説明文を含む）には一切かからない。

4. **held-out評価**：学習に使ったデータとは別に生成した，一度も見せていない入力で正解率を測定する。学習用と評価用でチャレンジの乱数シード空間を分離しており，重複しないことを保証している。

5. **学習条件**：学習1000件・5エポックを標準としている（1000件という数は，比較対象であるCNNの学習データ量に揃えたもの）。

## 記号の定義（原論文の記法）

### 秘密写像 σ（＝本報告で「鍵」と呼んでいるもの）

$$\sigma : [n] \to \mathbb{Z}_{10}$$

$[n]$ は $1$ から $n$ までの自然数の集合 $\{1, 2, \dots, n\}$，$\mathbb{Z}_{10}$ は10で割った余りの同値類，すなわち1桁の整数の集合 $\{0, 1, \dots, 9\}$ である。つまり $\sigma$ は，画像や文字など n 個のオブジェクトから10進数の数字への写像であり，ユーザーはこれを暗記する。

### チャレンジ C

$$C_i \in [n]^k$$

$C_i$ は $i$ 番目のチャレンジ，$[n]^k$ は集合 $[n]$ の直積を $k$ 回とったもの，すなわち $[n]$ の要素を並べた長さ $k$ の列の全体である。

ここでの $k$ は「1回のチャレンジで提示するオブジェクトの個数」＝チャレンジ長であり，関数 $f$ が受け取る入力の個数と一致する（原論文は一般形を $f : \mathbb{Z}_{10}^k \to \mathbb{Z}_{10}$ と書く）。**この $k$ は，後述する関数族のパラメータ $k_1$・$k_2$ とは別のものである**。両者には $k = 10 + k_1 + k_2$ という関係がある。

### レスポンス

$$f(\sigma(C))$$

$\sigma(C)$ は，チャレンジ $C = (C_1, C_2, \dots, C_k)$ の各要素に秘密写像 $\sigma$ を適用したもの，すなわち $(\sigma(C_1), \sigma(C_2), \dots, \sigma(C_k))$ である。サーバは公開されたチャレンジを提示し，ユーザーは暗記した $\sigma$ で数字に直してから関数 $f$ を暗算し，その結果を答える。

## 本研究のパラメータと原論文の設定の対応

今週，原論文で確認した内容である。

| | 本研究 | 原論文 |
| :--------------- | :-----------: | :------------------------------------ |
| $n$（$\sigma$ のマス数） | 10 または 26 | 説明用の例示として n=26 を挙げるが，実験・公開チャレンジの主軸は n=50・100。著者自身は n=100 を約2時間で暗記したと報告 |
| $k$（チャレンジ長） | 14 | 14（入力変数は $10+k_1+k_2$ 個。$(k_1,k_2)$ が (1,3)(2,2)(3,1) のいずれでも14で揃う） |

: 本研究のパラメータと原論文の設定の対応

プログラム中の `sgm` が $\sigma$，`X[i]` が $C_i$ にあたる。$n$ と $k$ は独立なパラメータであり，直接の関係はない。

なお原論文は n=26 を**安全性が不十分**と明示している（"the value n = 26 is too small to provide UF-RCA security even with small values of m"）。CSPソルバー攻撃（$f_{22}$）の結果は次の通りで，n=26 は全条件で破られている。

| n | m=50 | m=100 | m=1000 | m=10000 |
| :-----: | :------: | :------: | :------: | :------: |
| 26 | 23.5時間 | 40分 | 10分 | 2分 |
| 30 | HARD | UNSOLVED | 10分 | 20秒 |
| 50 | HARD | HARD | UNSOLVED | 7時間 |
| 100 | HARD | HARD | HARD | UNSOLVED |

: CSPソルバー攻撃（$f_{22}$）による鍵の復元にかかる時間

したがって本研究が n=26 や n=10 を用いる理由は「安全な設定を再現するため」ではなく，**LLMの能力を測るベンチマークとして，差が観測できる難易度水準を選んだため**である。この区別は卒論で明記する必要がある。なお $n$ を大きくすると $\sigma$ の暗記負荷が上がるため，安全性と可用性は原理的にトレードオフの関係にある。

**Stage（情報開示レベル）**：0=ヒントなし，1=$\sigma$開示・ルール非開示，2=ルール（関数 $f$）は開示するが $\sigma$ は非開示，3=ルール開示＋$\sigma$の一部を開示。本研究は主にStage 2で行っている。

このStage 2という設定は恣意的なものではなく，**原論文の攻撃者モデルと厳密に一致する**ことを今週確認した。原論文の Password Unforgeability game（Definition 2）には *"The adversary is given the function f … and is shown the challenges"* と明記されており，「アルゴリズムは既知，鍵のみ秘密」というケルクホフスの原理に立脚した設定になっている。つまり本研究がルールを開示して鍵だけを隠すのは，原論文の安全性証明の前提そのものである。

## 人間計算可能関数 $f_{k_1,k_2}$

原論文が提案する関数族は次の形をしている。

$$f_{k_1,k_2}(x_0, x_1, \dots, x_{9+k_1+k_2})
   = x_j + \sum_{i=10+k_1}^{9+k_1+k_2} x_i \pmod{10}$$

$$\text{ここで}\quad j = \left( \sum_{i=10}^{9+k_1} x_i \right) \bmod 10$$

入力変数は $10 + k_1 + k_2$ 個＝チャレンジ長 $k$ である。入力ベクトルは $x = (\sigma(C_0), \dots, \sigma(C_{9+k_1+k_2}))$，すなわちチャレンジに $\sigma$ を適用した後の数字列である。$k_1$ 個の項を足して添字 $j$ を作り（＝どこを見るかを決める），参照した値 $x_j$ にさらに $k_2$ 個の項を足して答えとする。先頭の10個（$x_0$〜$x_9$）は動的参照の飛び先として確保される（$j$ が $\bmod 10$ で決まるため）。

本研究の主対象 `func_22` は $(k_1, k_2) = (2, 2)$ の場合にあたる。

## 安全性パラメータ $s(f)$

原論文は，攻撃者が $\sigma$ を復元するのに必要な観測数が $m = \tilde{\Omega}(n^{s(f)})$ であると示しており，その指数 $s(f)$ を次のように定義している。

$$s(f) = \min\left\{ \frac{r(f)}{2},\ g(f)+1 \right\}$$

$r(f)$ は**分布的複雑度**，すなわち出力に偏り（相関）を生じさせないために固定しなければならない最小の入力変数数であり，提案関数では $r(f_{k_1,k_2}) = k_2 + 1$ である。$g(f)$ は**線形化変数数**，すなわち完全な線形方程式に退化させるために固定しなければならない最小の入力変数数であり，$g(f_{k_1,k_2}) = \min\{k_1, 10\}$ である。これを代入すると

$$s(f_{k_1,k_2}) = \min\left\{ \frac{k_2+1}{2},\ k_1+1,\ 11 \right\}$$

となり，`func_22` では $s(f) = 1.5$ である。

この $r(f)$ の定義「出力に偏りを生じさせないために固定すべき変数数」が $k_2+1$ であることは，**最後の加算項 $k_2$ が出力分布の偏りを打ち消す役割を担っている**ことを意味する。今週の結果（2節）は，この構造が実際に効いていることを示している。

## 難易度の分解と，扱っている関数の定義

本命の関数 `func_22` の難しさを3要素に分解し，簡単な要素から単独で検証できるよう診断用の関数を作成している。`sgm[i]` は鍵の i 番目，`X[i]` はチャレンジの i 番目を表す。

+----------------------------+----------------------------------------------------------------------------+-------------------------------+
| 名称                       | 計算式                                                                     | 検証する要素                  |
+============================+============================================================================+===============================+
| lookup\_k                  | $Z = \text{sgm}[X_0]$                                                      | ①記憶：表を正しく参照できるか |
+----------------------------+----------------------------------------------------------------------------+-------------------------------+
| table\_add\_k              | $Z = (\text{sgm}[X_0] + \text{sgm}[X_1]) \bmod 10$                         | ①+②合成：2箇所参照して足す    |
+----------------------------+----------------------------------------------------------------------------+-------------------------------+
| pointer\_k                 | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 10$                   | ③動的参照のみを単独抽出       |
|                            |                                                                            |                               |
|                            | $Z = \text{sgm}[X_j]$                                                      |                               |
+----------------------------+----------------------------------------------------------------------------+-------------------------------+
| func\_22（本命）           | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 10$                   | ①+②+③すべて                   |
|                            |                                                                            |                               |
|                            | $Z = (\text{sgm}[X_j] + \text{sgm}[X_{12}] + \text{sgm}[X_{13}]) \bmod 10$ |                               |
+----------------------------+----------------------------------------------------------------------------+-------------------------------+

: 難易度を3要素に分解した診断用の関数

「動的参照」とは，計算の途中で求めた数値 j を使ってチャレンジの j 番目の要素を新たに読みに行き，その値をさらに鍵で変換する，という間接参照の構造を指す。

## 8月にご指示いただいた課題と，追加した関数

8月に「人間計算可能性を少し犠牲にしても，動的参照構造を増やす方向でLLMの限界を探る」というご指示をいただき，ご共有いただいた資料（8/1）で挙げられていた候補のうち，優先度の高い3種類を実装した。いずれも本命の `func_22`（動的参照が1本）を出発点に，**動的参照の本数や繋ぎ方を変えた**ものである。

### pointer\_chain（深さ方向・直列に反復）

$$\begin{aligned}
j &= (\text{鍵}[X_{10}] + \text{鍵}[X_{11}]) \bmod 10 \\
j &\leftarrow \text{鍵}[X_j]
   &&\text{… これを（深さ$-1$）回くりかえす} \\
Z &= \text{鍵}[X_j]
\end{aligned}$$

同じ操作「指した先を見て，その値が示す位置をまた指す」を繰り返す。深さ1は既存の `pointer_k` と一致する。**足し算を含まない**（$k_2=0$）のは，深さの効果だけを取り出すためである。今週まで実験してきたのはこれである。

### dualptr（並列・独立な2本）

$$\begin{aligned}
j_1 &= (\text{鍵}[X_{10}] + \text{鍵}[X_{11}]) \bmod 10 \\
j_2 &= (\text{鍵}[X_{12}] + \text{鍵}[X_{13}]) \bmod 10
     &&\text{… $j_1$ とは無関係に決まる} \\
Z   &= (\text{鍵}[X_{j_1}] + \text{鍵}[X_{j_2}]) \bmod 10
\end{aligned}$$

動的参照を2本に増やすが，**互いに依存しない**。2箇所を別々に見に行って足す形なので，反復（前の結果を次の入力にする）は含まない。資料では「最大候補（私の本命）」と位置づけられていた。

### recptr（直列・依存あり）

$$\begin{aligned}
j_1 &= (\text{鍵}[X_{10}] + \text{鍵}[X_{11}]) \bmod 10 \\
j_2 &= (\text{鍵}[X_{j_1}] + \text{鍵}[X_{12}]) \bmod 10
     &&\text{… $j_1$ の参照結果が $j_2$ の計算に入る} \\
Z   &= (\text{鍵}[X_{j_2}] + \text{鍵}[X_{13}]) \bmod 10
\end{aligned}$$

2本目のポインタ $j_2$ を求めるのに1本目の参照結果 $\text{鍵}[X_{j_1}]$ を使うため，**参照同士に依存関係がある**。`func_22` の依存を一段強めた形にあたる。`pointer_chain` と似ているが，**各段で新しい項（$X_{12}$，$X_{13}$）を足す**点が決定的に異なる（2.3節）。

| 名称 | 動的参照の本数 | 参照どうしの関係 | 末尾の足し算 |
| :-------------- | :----------: | :--------------: | :----------: |
| func\_22（基準） | 1本 | — | あり |
| pointer\_chain | 深さ分（直列） | 前の結果が次の入力 | **なし** |
| dualptr | 2本 | 独立（依存なし） | あり |
| recptr | 2本 | 依存あり | あり |

: 8月に追加した3つの関数の比較

先週までに実験したのは `pointer_chain`（深さ）のみだったが，今週 `dualptr`・`recptr` も実験し，3つとも検証を終えた（2節）。

なお `dualptr`・`recptr` はいずれも末尾に足し算があり（$k_2 > 0$），足し算のない `pointer_chain`（$k_2 = 0$）とそのまま比べると「動的参照の構造」と「足し算の有無」が交絡する。そこで**動的参照1本＋足し算**の基準線として，`func_22` の鍵10マス版（`func_22_k10`）を今週新たに用意した。`func_22` は本来 $n = 26$ だが，$n = 26$ では動的参照の有無に関わらず崩壊して差が見えないため（1.9節），深さラダーと同じ $n = 10$ に揃えている。

## これまでの結果の要点（今回の報告の前提）

7月末までの報告で，経路B（ファインチューニング）について次の結果を得ている：

1. ①記憶と②合成は，十分なデータ量があれば学習できる（丸暗記ではなく，学習に使っていない入力の組み合わせでも高精度で汎化することを確認済み）。

2. ③動的参照を含む課題（func\_22, pointer\_k）だけは，データ量を5倍に増やしても改善しない。

3. ただし n=26 では動的参照の有無に関わらず崩壊するため，原因を切り分けられない。統制実験（動的参照を使わず3箇所を参照して足すだけの `table_add3`）と比較したところ，n=10 では動的参照の有無で明確な差が出た（100% vs 34%）が，n=26 では両方とも低い値で頭打ちになった。値の組み合わせ数（$26^3 \approx 17{,}576$通り）そのものが支配的になるためと考えられる。**以降の実験が n=10 を用いているのは，差が観測できる水準を選んだためである。**



# 今週の結果

## 動的参照を1本から2本に増やしても，精度は変わらなかった

1.8節の3つの関数を，動的参照の構造だけを変数にした3点比較として実験した。条件は深さ方向の実験と完全に同一（Stage 2，学習1000件，5エポック）で，鍵は先週の再評価で使った偏りの少ない2種類，評価は500件である。

| 関数 | 動的参照 | 鍵A | 鍵B | 衝突確率 |
| :--------------------------- | :------------------ | :---: | :---: | :---------: |
| `func_22_k10`（基準線） | 1本 | 13.0% | 16.0% | 10.0 / 10.5% |
| `dualptr` | 並列2本（独立） | 14.4% | 13.8% | 10.3 / 12.0% |
| `recptr` | 直列2本（依存あり） | 10.4% | 20.0% | 10.1 / 11.4% |

: 動的参照の構造を変えた3点比較（$n = 10$，評価500件）。衝突確率は「正解の分布を完全に知った上で独立に引く」戦略の的中率で，鍵ごとに異なる

**基準線との差は，どの比較でも統計的に有意ではなかった。** 鍵ごとのFisher exact検定で $p = 0.118$〜$0.581$，両鍵をまとめた検定（Cochran-Mantel-Haenszel）でも `dualptr` が $p = 0.848$，`recptr` が $p = 0.705$ である。**動的参照を1本から2本に増やしても，並列・直列のいずれでも精度は変わらない。**

## より重要な問題として，全条件が床に張り付いていた

上記の表で注目すべきは，個々の差ではなく**6条件すべてが10〜20%の範囲に収まっている**ことである。偶然水準は10%であり，**基準線の時点で既に床に近い**。

各条件が衝突確率を有意に上回るかを二項検定で確認したところ，上回るのは6条件中4条件にとどまった（`recptr` 鍵Aは $p = 0.423$，`dualptr` 鍵Bは $p = 0.128$ で，当てずっぽうと区別できない）。

**基準線が床にある以上，「参照を増やすと難しくなる」という仮説は原理的に検証できない。** 下がる余地が残っていないためである。今回の結果は「構造の違いに効果が無い」ことの証拠としては弱く，「現在の設定では識別できない」と述べるのが正確である。

## 実験設計そのものは健全だった

深さ方向の実験では，足し算が無いために鍵の数字の偏りがそのまま答えの偏りになるという交絡があった（3.4節）。今回の3関数はいずれも末尾に足し算があるため，実験前に設計上の衝突確率を確認したところ，3関数・2鍵の全てで10.0〜12.0%と偶然水準の近傍にあった。

実際の予測分布を見ても，深さ方向で見られたような「鍵に無い数字を一度も予測しない」といった構造的な偏りは生じていない。**交絡の除去には成功しており，正解率をそのまま読める状態になっている。** その上で差が出なかった，というのが今回の結果である。

## 副産物：$n = 10$ は足し算のある関数では床だった

7月の実験で `pointer_k10`（足し算なし）が34%を示していたため，$n = 10$ を「差が観測できる水準」として選び，以降の実験もこれを引き継いでいた（1.9節）。

しかし今回，**足し算を入れて鍵の偏りを除くと $n = 10$ でも13〜16%まで落ちる**ことが分かった。34%という数字は鍵の偏りによる嵩上げだったことになる。$n = 10$ が観測に適していたのは足し算のない関数に限った話であり，**足し算を含む関数では $n = 10$ でも床だった**。

## 学習データ量を5倍にしても，基準線は床から動かなかった

床に張り付いている原因が「学習量の不足」なのかを確かめるため，基準線 `func_22_k10`（key\_seed=1）の学習件数だけを 1000 / 3000 / 5000 件と振った。他の条件（モデル・エポック数・鍵・評価500件）はすべて同一である。

: 学習データ量スイープ（`func_22_k10`，key\_seed=1，評価500件）

+------------+----------+-----------------+---------------------+
| 学習件数   | 正解率   | 95%信頼区間     | $p$（衝突確率10.0%\  |
|            |          |                 | に対する片側検定）  |
+============+==========+=================+=====================+
| 1000件     | 13.0%    | [10.3%, 16.2%]  | 0.018               |
+------------+----------+-----------------+---------------------+
| 3000件     | 12.2%    | [9.6%, 15.4%]   | 0.062               |
+------------+----------+-----------------+---------------------+
| 5000件     | 12.6%    | [10.0%, 15.8%]  | 0.034               |
+------------+----------+-----------------+---------------------+

**まったく動かなかった。** 1000件と5000件の差は Fisher の正確検定で $p = 0.92$，3000件と5000件でも $p = 0.92$ である。3水準とも信頼区間の下限が衝突確率（10.0%）に接しており，実質的には「偶然当たっている水準」から出ていない。

この結果は，7月からの積み残しに決着をつける。7月には「$n = 26$ では動的参照の有無に関わらず崩壊するが，値の組み合わせ数（$26^3 \approx 17{,}576$通り）が支配的なせいかもしれず，動的参照固有の効果と区別できない」と保留していた（1.9節）。今回の $n = 10$ では値の組み合わせは $10^3 = 1000$ 通りしかなく，5000件はその5倍を覆う。それでも上がらない以上，**崩壊の原因は組み合わせ爆発ではなく動的参照そのもの**だと言える。

同時に，ファインチューニングの学習量を増やす方向では基準線を持ち上げられないことも確定した。したがって前節の「構造の効果は識別できない」という状態は，この軸では解消できない。

# 今週得られた方法論上の知見

## 基準線を先に測らないと，比較実験は解釈できない

今回，基準線（`func_22_k10`）を最初に回す順序にしたことで，「差が無い」のか「そもそも識別できない設定なのか」を区別できた。基準線を後回しにしていれば，`dualptr` 14.4% と `recptr` 10.4% という数字だけを見て「直列の方が難しい」と誤読していた可能性が高い。

比較実験では，**基準線を最初に確保する**ことを今後の手順とする。

## 「床に張り付いている」ことは，差が無いこととは違う

先週の知見（4.2節）は「偶然より高いだけでは精度が出ているとは言えない」だったが，今回はその裏返しにあたる。**測定対象が床にあるとき，条件間の差が無いことは「効果が無い」証拠にならない。** 効果があっても現れようが無いためである。

否定的な結果を報告する際は，「効果が無かった」ではなく「この設定では識別できなかった」と書き分ける必要がある。

# 次にやること（Next Actions）

8月にご指示いただいた課題（動的参照を増やす方向でLLMの限界を探る）については，提案されていた候補のうち優先度上位の3つを全て検証し終えた。結果はいずれも仮説を支持しなかったが，その主因は**測定が床に張り付いていること**であり，構造の効果を否定できたわけではない。

そして今週，その床が学習データ量では動かないことも確認した。**ファインチューニングという枠組みの中で動的参照の構造の効果を測ることは，現状では難しい**と考えている。

## 案1：鍵サイズ $n$ を小さくして可観測域を探す

$n = 10$ でも $n = 26$ でも床だった。$n$ をさらに小さくすれば（例えば $n = 4$ や $n = 6$），鍵の記憶量が減って基準線が上がる可能性がある。ただし $n$ を小さくすると鍵の値の種類が減り，偏りによる交絡が再び強くなる（3.4節）ため，衝突確率を事前に確認した上で選ぶ必要がある。また $n$ を小さくすることは原論文の安全性の想定（$n = 100$ 程度）から遠ざかる方向であり，得られた差をHCPの安全性の議論に接続しにくくなる。

## 案2：経路A（in-context推論）へ進む

卒研計画の第2期にあたる。ファインチューニングでは学習量・鍵サイズのどちらを振っても床から出られないことが分かった以上，**学習させずにプロンプトの例だけで解かせる設定**に移るのが自然だと考えている。この設定では，鍵を与えた上でルールだけを推論させる／ルールを与えた上で鍵を推論させる，といった問題の切り分けが可能であり，「床」に相当する状態も変わりうる。
