対象: 「人間計算可能なパスワード（Human-Computable Passwords, HCP）」LLM推論限界評価

## 1. 前回までの流れ（経緯の整理）

本報告の位置づけを明確にするため，これまでの経緯を要約する。

1. **研究の枠組み（6月）**: HCPを「データ汚染のない推論ベンチマーク」として再定義し，情報開示レベル（Stage 0〜3）・ペア数 N・鍵部分開示数 K を振って，LLMの推論が崩壊から成功へ転じる**相転移境界**を測る計画を立てた。
2. **ファインチューニング実験（6月末〜7月上旬）**: QLoRAによる学習で鍵推論を試みたが，2つの問題に直面した。
   - **PoTパラダイムの鍵リーク**: 教師コードに正解の秘密鍵がリテラルとして埋め込まれており，見かけ上の正解率100%は丸暗記によるものだった（研究の前提を満たさない）。
   - **Pureパラダイムのモード崩壊**: 予測が少数の固定値に集中（正解率5〜20%）。rationale追加・LoRAランク増・学習率低下・データ量10倍のいずれでも解消せず，鍵を使わない `simple_add` でも同様に崩壊した。
3. **評価スクリプトのバグ発見（前回報告）**: `--provider lora` 時に stage 設定が強制的に0へリセットされ，学習条件と評価条件が食い違っていたことが判明。「ルール開示の効果なし」という結論は保留とした。

今週は，これらの行き詰まりの**根本原因をコードレベルで総点検**し，その結果に基づいて**研究計画の見直し（v2）とコードベースの全面リファクタリング**を実施した。

## 2. Copilotレビュー（7/7）のご指摘への対応

前回レビューでいただいた指摘それぞれについて，対応状況を明示する。

### 指摘A: 「PoTリーク問題よりも simple_add での失敗の方が根本原因解明に近い」

**対応: コードベース全体の監査を実施し，ご指摘の方向性を裏づける問題を複数発見した。**

学習タスクの難しさ以前に，実験パイプライン側に研究の妥当性を損なう問題が4件存在した（詳細: `docs/refactor_notes.md`）。

| # | 発見した問題 | 影響 |
|---|---|---|
| 1 | **FTの評価テスト問題が学習データと重複**（学習と評価が同一シードから同一データ列を生成しており，ホールドアウト評価になっていなかった） | 従来のFT正解率5〜20%は実質「学習データ上での精度」。**それでもこの水準だったことは，モード崩壊のより強い証拠** |
| 2 | 主要評価指標「鍵復元率（Key Recovery Rate）」が未実装（応答予測の正解率のみ測定） | 「鍵の逆推定」の直接証拠が測れない状態だった |
| 3 | 全実験が単一の鍵（seed=42）で実施 | 成功「率」・相転移の主張に必要な複数鍵での反復が不可能だった |
| 4 | アルゴリズム定義が4ファイルに重複 | PoT鍵リークはこの重複の中で生じた（再発する構造だった） |

### 指摘B（優先度1）: 「教師データを数件目視確認せよ（tokenizer / EOS / JSON整形 / ラベルマスク）」

**対応: 監査の過程で，ラベルマスク等の不具合説を弱める定量的傍証を得た。目視確認と合わせて来週の過学習テストで最終決着させる。**

旧FT実験の学習曲線（`loss≈0.19`, `token_accuracy≈0.92〜0.93` で横ばい）を再解釈したところ，教師 completion `{"answer": <数字>}`（約13トークン）のうち**書式トークンを完全に学習し，answer の数字1トークンだけが偶然水準（1/10）に留まる**と仮定した場合の理論値（token_accuracy ≈ 12/13 + (1/13)×0.1 ≈ 0.93，loss ≈ ln(10)/13 ≈ 0.18）と**定量的に一致**した。これは「パイプラインは正常に動作しており，数字を当てるための勾配信号が不足している」という解釈を支持する。

### 指摘C（優先度2）: 「train=20件の過学習テストを最優先で実施せよ」

**対応: 修正済みパイプラインで実施し，合格した。**

- 条件: Qwen2.5-3B / 4bit QLoRA / simple_add / train=20件×30エポック（§4の(B)条件: Few-shot例なし）。
- 結果: train loss は **4×10⁻⁵** まで収束し token_accuracy=1.0（旧実験の loss≈0.19 横ばいは再現せず）。学習セット上の生成評価で **20/20 = 100%**。
- 結論: **パイプライン（tokenizer / EOS / JSON整形 / ラベルマスク）は健全**。以降の否定的結果はパイプラインではなくタスク・学習方式に帰属できる。

### 指摘D（優先度3）: 「最小問題（(X0 + secret) % 10）で秘密鍵推論の可否を検証せよ」

**対応: ご提案のアルゴリズム（`secret_add`, 鍵1桁）を実装・実施し，成功した。**

- 条件: ルールは自然言語で開示（Stage 2）・秘密値のみ非開示，n_train=200×5エポック，評価は学習と互いに素な held-out 50件。
- 結果: **held-out 正解率 100%（50/50，パースエラー0）**。秘密の1桁は SFT で重みに格納できる。
- 含意: 「LLMのSFTでは鍵が重みに入らない」という前回までの見立ては，修正後の設計では**成立しない**。旧モード崩壊の主因は，タスクの本質的困難ではなく旧設計の欠陥（§2指摘A: Few-shot混入・ホールドアウト不成立・学習/評価の条件食い違い）であった可能性が極めて高い。研究の問いは「**鍵は何桁・どんな構造まで重みに入るのか（記憶容量と構造の境界探索）**」へ更新される。

## 3. 今週の主な成果

### 3.1 研究計画の見直し（v2ドラフト，`docs/plan_v2_draft.md`）

以前のモンテカルロ検証で「n_shot=10 では整合する鍵候補が10^16通り残り，一意特定には N≈26〜50 が必要」と判明していたことを研究の核に据え，主軸を次のように再定式化した:

> **情報理論的に解ける領域（N ≥ N\*_info）で，LLMは実際どこから解けるようになるか（N\*_LLM）。そのギャップがLLMの帰納推論の欠損の定量値である。**

これにより，(1) 情報限界，(2) 厳密ソルバーによる計算可解性，(3) 偶然水準，の3本の基準線に対してLLMの成績を位置づけられ，**LLMが全条件で失敗しても「情報不足」「計算不能」と切り分けた否定結果として成立する**構造になった。FTは補助実験（§4）に位置づけを変更した。

### 3.2 コードベースの全面リファクタリング

- アルゴリズム定義を単一情報源化（`code/hcp/algorithms.py`，計算とコード表現の整合を機械検証）
- **鍵復元タスク `recover_key` を新実装**（鍵テーブルを丸ごと逆推定させ，セル一致率・完全一致率・held-out精度を測定。1条件1リクエストでAPIコストは従来比約1/50）
- 鍵シードとデータシードを分離し，複数鍵での反復（成功率測定）を1コマンド化
- 全実験でプロンプト実物・gitコミットを保存（前回のstageリセットバグのような条件食い違いを即検出可能に）
- N×K×シードの相転移スイープハーネス（中断・再開対応）を整備

### 3.3 厳密ソルバーの実装と初期結果（v2計画の基準線）

制約充足探索（動的変数順序＋単位伝播）による整合鍵の数え上げ・復元ソルバーを実装した。初期結果:

| 条件（func_22, 鍵26マス） | 結果 |
|---|---|
| N=10 | 整合鍵 10万個超（情報不足領域の確認） |
| N=100〜200 | **鍵の一意性を厳密証明し，真の鍵を完全復元（20〜30秒）** |
| func_pow, N=100 | **整合鍵が2個残存** — x^k mod 10 の縮退により鍵は原理的に一意特定不能（ただし応答予測には影響しない可能性が高く，考察の材料になる） |

「ルール既知なら古典的探索で鍵は復元できる」ことが実証されたため，今後のLLMの失敗は**情報不足でも計算不能性でもなく推論の失敗**として解釈できる。

鍵リーク・ホールドアウト不成立の旧FTモデル重み（約3.2GB）を削除（Google Driveにバックアップ保持）。学習メタデータ・損失ログ・評価生ログは否定的知見の一次資料として保全した。

## 4. 学習実験（CNN路線）の扱いについて

本研究には「**(A) in-context型**（プロンプト内のFew-shot例から推論時に鍵・規則を読み取る）」と「**(B) 重み格納型**（大量の X→Z ペアの学習で鍵・規則を重みに焼き付ける。CNN・先行研究の枠組み）」の2つのパラダイムが混在しており，従来のFT実験は(B)を測るべきところにプロンプティング実験由来のFew-shot例（(A)の道具立て）が混入していた。これでは正解時に「重みに入った」のか「プロンプト内の例から読み取った」のか区別できず，CNNとの情報条件も揃わない。

そこで**学習実験は全面的に(B)へ寄せる**: プロンプトはFew-shot例なし（`n_shot=0`）の最小形式（Input と回答形式指示のみ）とし，CNNと同じ「X→Zの直接対応の学習」だけを測る。(A)はプロンプティングによる相転移測定（v2計画の主軸）が正式に担当する，と役割を分離した。

先輩方のCNN研究の延長としての「学習による結果」は，この(B)条件で**CNNと条件を極力揃えた公平比較として決着させる**。CNNベースラインの学習データは1000件であり，LLM側も同規模で揃えられる。

| 段階 | 内容 | 目的 | 状況 |
|---|---|---|---|
| 1 | 過学習テスト（train=20） | パイプライン健全性の最終確認（レビュー優先度2） | **合格**（20/20） |
| 2 | 最小タスク（鍵1桁） | 鍵1個の学習可否の切り分け（レビュー優先度3） | **成功**（held-out 100%） |
| 3 | 鍵サイズ・構造の境界探索 ＋ CNN同条件比較（Few-shot例なし・n_train=1000・held-out評価） | 「何桁・どんな構造まで重みに入るか」の測定と CNN vs QLoRA の公平比較 | **実施済み（下記）** |
| 4 | （余力があれば）Qwen2.5-0.5B のフル微調整 | 「LoRAの表現力不足」という交絡の排除 | 未着手 |

### 段階3の結果（7/16夜〜7/17実施，held-out 50件，図: `results/figures/stage3_boundary.png`）

func_22 が同時に含む3つの困難（①鍵テーブルの記憶量，②参照値の算術合成，③ポインタ間接参照）を分離する「難易度ラダー」を構成し，QLoRA と CNN を同一データ量（n_train=1000）で比較した。

| 条件 | LLM (3B QLoRA) | CNN | 分離される要因 |
|---|---|---|---|
| secret_add（鍵1桁） | 100% | 94% | — |
| lookup_k4/k10/k26（純テーブル参照） | すべて 100% | すべて 100% | ①記憶量 |
| table_add_k10（表10マス+mod和） | 100% | 88% | ①+② |
| **table_add_k26（表26マス+mod和）** | **8%** | **51%** | ①+② |
| **func_22（+ポインタ）** | **12%**（ルール開示の有無で不変） | 7% | ①+②+③ |
| simple_add（鍵なし・生入力の加算） | **100%** | **10%** | 統制条件 |

**主な知見**:

1. **記憶量①は律速ではない**（26マスの純テーブルは完全に学習可能）。境界は「②算術合成 × 表の大きさ」にあり，**k=10 と k=26 の間**で 100%→8% に崩落する。
2. **func_22 の学習失敗は本質的困難と確定**。健全性を確認済みのパイプラインで旧実験と同一の崩壊シグネチャ（loss≈0.192, token_accuracy≈0.925 = 「answer数字のみ偶然水準」）が再現し，ルール開示でも改善しなかった。先週までの「モード崩壊」は，バグに汚染されてはいたが方向としては実在の現象だったことになる。
3. **LLMとCNNは失敗の仕方が質的に異なる**。記号的規則（simple_add）は LLM 100% vs CNN 10%，大きな表の関数近似（table_add_k26）は CNN 51% vs LLM 8%。「事前学習知識と合成できる規則は LLM が強く，生の関数近似は CNN が粘る」という対比が得られた。
4. 留意事項: 1鍵シードのみ・学習予算固定（5エポック）での探索結果であり，境界付近は複数シード・データ増量での確認を次週行う。

**次の実験**: (a) 境界の精密化（table_add の k=13,16,20），(b) 失敗モデルに鍵テーブルを出力させる内省検査（`recover_key`）で「どのセルが重みに入ったか」を特定，(c) n_train=5000 で「データ不足か能力限界か」を切り分け，(d) 境界付近のみ3鍵シードで再現確認。

段階1・2の成功により，**FT路線（学習による結果）は有効な研究軸として復活した**。焦点は「学習できるか否か」から「鍵サイズ（1→26桁）と構造（テーブル参照・ポインタ間接参照）に対する学習可能性の境界」へ移る。8月からのv2相転移スイープ（in-context型）と対になる「重み格納型の境界測定」として位置づける。

### 4.1 段階3の結果 — 学習可能性の境界を特定（図: `results/figures/stage3_ladder.png`）

func_22 が同時に含む3つの困難（①鍵テーブルの記憶量，②参照値の算術合成，③ポインタ間接参照）を1段ずつ分離する「難易度ラダー」を実装し，一括実行した（各 n_train=1000, 5エポック, held-out評価）。

| 条件（何を測るか） | QLoRA 3B | CNN (1000件) |
|---|---|---|
| simple_add — 生入力の算術規則 | **100%** | 10%（偶然水準） |
| secret_add — 鍵1桁 | **100%** | 94.5% |
| lookup k=4/10/26 — ①記憶のみ | **100% / 100% / 100%** | 100% / 100% / 100% |
| table_add k=10 — ①+②合成 | **100%** | 88% |
| table_add k=26 | **8%（崩壊）** | 51% |
| func_22 — ①+②+③ポインタ | 12%（崩壊） | 7% |

主要な発見:

1. **境界は「記憶量」ではない**。26セルのテーブル参照は完全に学習できる（lookup_k26 = 100%）。
2. **LLMの崩壊点は「参照の合成 × 入力クラス数」の間にある**。table_add は k=10（入力ペア100通り）で100%だが，k=26（676通り）で8%へ急落する。学習中に出現したペアに限定しても8%であり，**この段では暗記すら成立しない**（k=10では100ペアの完全暗記が可能だった）。崩壊時の損失は旧実験と同一のシグネチャ（loss≈0.19, token_accuracy≈0.93）を示す。
3. **学習器による得意構造の対比**: table_add_k26 では CNN（51%）> LLM（8%）と部分汎化の差が出る一方，simple_add では LLM（100%）≫ CNN（10%）と完全に逆転する。後者は事前学習で獲得済みの算術回路の再利用と解釈でき，「LLMは既知の演算の再利用に強く，新規のテーブル合成の獲得に弱い」という構図が得られた。
4. ポインタ間接参照（func_22）は両学習器とも n_train=1000 では全滅。

### 4.2 段階3b — 崖の細分化と露出回数仮説の検証（図: `results/figures/stage3b_cliff.png`）

k=26 での崩壊が「クラスあたり露出回数の不足」か本質的限界かを切り分けるため，(1) k=13/16/20 で崖の位置を細分化し，(2) k=26 と func_22 を n_train=5000 で追試した。

| 条件 | クラス数 k² | 露出回数/クラス（≈5·n_train/k²） | held-out |
|---|---|---|---|
| table_add k=13 (n=1000) | 169 | ≈30 | **100%** |
| table_add k=16 (n=1000) | 256 | ≈20 | **100%** |
| table_add k=20 (n=1000) | 400 | ≈12.5 | 24% |
| table_add k=26 (n=1000) | 676 | ≈7.5 | 8% |
| **table_add k=26 (n=5000)** | 676 | ≈37 | **100%（復活）** |
| **func_22 (n=5000)** | —（実効クラス空間が巨大） | — | **12%（崩壊のまま）** |

結論:

1. **table_add の崩壊は露出回数でほぼ説明できる**（成功の目安 ≈20回/クラス）。テーブル参照の合成は**データ量の問題であり本質的限界ではない**。ただし n=5000 では全クラスが学習中に出現するため「合成の獲得」ではなく「全クラスの暗記」の可能性が残る（一部ペアを学習から除外する実験で切り分け予定）。
2. **ポインタ間接参照（func_22）だけはデータを5倍にしても崩壊したまま**。難易度ラダーの3要素（記憶量・合成・ポインタ）のうち，**唯一残った本質的困難はポインタ**であると特定できた。これは HCP の構造的難しさの根拠を学習実験の側から与える結果であり，8月からの in-context 相転移測定（v2主軸）でも同じ要素分解で比較する。
