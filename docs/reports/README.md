# 週次報告の書き方とPDF化

原本は **Markdown**（`weekly_report_YYYYMMDD.md`）。そこから pandoc + Typst で直接
PDF を組む。**Word は経由しない。**

```
weekly_report_YYYYMMDD.md   ← 唯一の原本。AIエージェントが編集するのもこれ
template.typ                ← pandoc と js パッケージの橋渡し。体裁自体は持たない
preview.html                ← 手元のブラウザ用ライブプレビュー
pdf/                        ← 生成物（.gitignore 済み。いつでも再生成できる）
```

体裁は Typst Universe の **[js](https://typst.app/universe/package/js/)** パッケージ
（奥村晴彦氏，LaTeX の jsarticle / jsbook 相当）に任せている。日本の学術文書で
見慣れた体裁で，独自の装飾は入れていない。章・節の採番，見出しの体裁，行送り，
表の罫線，「表 1」「図 1」の採番はすべて js の既定である。

## 使い方

`nix develop`（direnv 済みなら自動）に入ってから，リポジトリのルートで：

| コマンド | すること |
| :------------------- | :--------------------------------------------- |
| `make report` | 全ての週次報告を PDF 化 |
| `make report-latest` | 日付が最新の1本だけ PDF 化 |
| `make report-live` | プレビュー配信＋自動再ビルド（**通常はこれ**。既定 8765番） |
| `make report-watch` | 保存を検知して再ビルドするだけ |
| `make report-send` | 最新PDFを Taildrop で手元の端末へ送る |

### 書きながらプレビューする

研究室のマシンには画面が無いので，PDFビューアではなく手元の端末のブラウザで見る。
**窓は1つでよい。** 手元の端末から，ポート転送を付けて SSH する：

```
ssh -L 8765:localhost:8765 labpc
```

繋がった先で：

```
make report-live
```

配信サーバと自動再ビルドが同時に立ち上がる（Ctrl-C で両方まとめて終わる）。あとは手元の
ブラウザで <http://localhost:8765/preview.html> を開くだけ。ポートが埋まっていたら
`PORT=9000 make report-live` のように変える。

保存すると1秒以内に表示が差し替わる。ヘッダの「戻るページ」に番号を入れておくと，
更新後もそのページに戻る（PDFビューアの都合で先頭に戻ってしまうため）。

## 書き方の約束

### 1. 先頭にフロントマターを置く

```yaml
---
title: 週次研究報告
subtitle: |
  対象：「人間計算可能なパスワード（Human-Computable Passwords, HCP）」LLM推論限界評価
author: 高橋成翔
date: 2026年8月19日
repo: <https://github.com/Naruto-Takahashi/human-computable-passwords.git>
section-numbering: "1.1"   # 章・節を自動採番する
toc: true                  # 目次を出す
toc-depth: 2               # 目次に載せる深さ
abstract: |                # 省略可。標題の下に「概要」として組まれる
  今週は…
---
```

タイトル・著者・日付・リポジトリはここから組まれる。本文に書き直さない。

**章番号は手で打たない。** `section-numbering` を指定すると自動で振られるので，
見出しは `# 前提知識` のように番号なしで書く（`# 1 前提知識` と書くと
「1 1 前提知識」になる）。節を入れ替えても番号が自動で追従する。

なお 2026-08-18 以前の報告書は見出しに番号を手打ちしているため，
`section-numbering` を書いていない（書くと二重になる）。

### 2. 数式は LaTeX 記法で書く

コードブロックや Unicode の下付き文字（`k₁`）で数式を代用しない。**組版されない上に，
読み手のLLMにも構造が伝わらない。**

```markdown
インラインは $s(f) = \min\{r(f)/2,\ g(f)+1\}$ のように書く。

$$f_{k_1,k_2}(x_0, \dots, x_{9+k_1+k_2})
   = x_j + \sum_{i=10+k_1}^{9+k_1+k_2} x_i \pmod{10}$$
```

複数行を揃えるときは `aligned` を使う。`&` が揃え位置，`&&` で注釈の列を作る。

```markdown
$$\begin{aligned}
j_1 &= (\text{鍵}[X_{10}] + \text{鍵}[X_{11}]) \bmod 10 \\
j_2 &= (\text{鍵}[X_{12}] + \text{鍵}[X_{13}]) \bmod 10
     &&\text{… $j_1$ とは無関係に決まる}
\end{aligned}$$
```

和文は `\text{…}` に入れる。プログラム中の識別子（`func_22`、`sgm`）は数式ではなく
バッククォートのコードのままにする。

### 3. 箇条書きと小見出しは記法どおりに書く

**番号つきの並びは `1.` で書く。** 行頭に `1 ` と数字だけ置いても，ただの段落に
なってぶら下げが効かない。

```markdown
1. **モデル**：ローカルで動かせる Qwen2.5-3B-Instruct を用いる。
2. **Bパラダイム**：Few-shot 例を含まない最小形式とする。
```

**小見出しは `###` で書く。** 太字だけの段落（`**秘密写像 σ**`）は本文に埋もれて
見えない。見出しにすれば採番もされ，目次にも載る。

```markdown
### 秘密写像 σ（＝本報告で「鍵」と呼んでいるもの）
```

### 4. 表と図にはキャプションを付ける

表の直後に `: ` で始まる行を置くと「表 1」「表 2」と通し番号が振られる。図も同様。

```markdown
| 鍵 | 深さ1 | 深さ2 |
| :--- | :---: | :---: |
| 鍵A | 24.8% | 24.2% |

: 評価件数500件での正解率（深さ方向の比較）
```

### 5. セル内で改行したい表は grid table にする

pipe table のセルは1行しか持てない。1つのセルに複数の式を入れたいときは
`;` で詰め込まず，grid table を使う。空行を挟むと段落が分かれ，別の行として組まれる。

```markdown
+------------------+--------------------------------------------+
| 名称             | 計算式                                     |
+==================+============================================+
| pointer\_k       | $j = (\text{sgm}[X_{10}] + \dots) \bmod 10$ |
|                  |                                            |
|                  | $Z = \text{sgm}[X_j]$                      |
+------------------+--------------------------------------------+
```

2つの注意点がある。

1. **`|` の位置は `+` と揃える。** 揃っていないと表として認識されず，`|` が
   そのまま出てしまう。全角文字は幅2として数える。
2. **1つのセルの中身は1行に収める。** ソース側で折り返すと，和文の場合その
   位置に半角空白が入ってしまう。長さは組版時に Typst が折り返してくれる。

列幅の比は `+---+` の長さの比で決まるので，長い式が入る列を長めに描く。

### 6. 表の列幅は区切り行のハイフン数で決まる

pipe table の2行目のハイフンの本数が，そのまま列幅の比率になる。数式や長い語が入る
列を長めに書くと折り返しが減る。

```markdown
| 名称 | 計算式 | 検証する要素 |
| :--------- | :------------------------------------------ | :---------------- |
```

`:---` は左揃え，`:---:` は中央揃え。数値の列は中央，数式や長い文の列は左が読みやすい。

### 7. 図は `figures/` に置く

SVG ならベクタのまま埋め込まれる（matplotlib なら `plt.savefig("...svg")`）。

```markdown
![深さごとの正解率](figures/depth_accuracy.svg)
```

### 8. 体裁を変えたいときは `template.typ` を触る

本文側に見た目の指定を書かない。原本の Markdown は，人間にもLLMにもそのまま読める
状態に保つ。

ただし `template.typ` は js への橋渡しであって，体裁の本体ではない。フォントや段組み
などは `js.with(...)` の引数で変えられる（指定できる項目は
[js のドキュメント](https://typst.app/universe/package/js/)を参照）。js の既定から
外れる変更は，理由をコメントに書いてから入れる。現在の変更点は次の3つだけである。

1. 見出しを太字にする（js の既定は weight 450 で，節の切れ目が追いにくいため）。
2. 表を三本線（booktabs 相当）にする（js の既定は全格子の細罫で，行数の多い数表
   だと見出し行と本体の区別がつかないため）。
3. 標題を js の `#maketitle` ではなくテンプレート側で組む（maketitle には副題と
   リポジトリの置き場が無く，項目ごとの間隔も広いため，標題まわりが散らかった上に
   目次が1ページに収まらなかった）。字面は js のままで，行間だけを詰めている。

## 補足

### フォントに Source Han を使っている理由

システムに入っている Noto CJK は**可変フォント**（`NotoSerifCJK-VF.otf.ttc`）で，
Typst は可変フォントに未対応のため**太字が出ない**（見出しが本文と同じ太さになる）。
`to_pdf.sh` のコメントにある，lualatex を諦めたのと同じ原因である。

Source Han は Noto CJK と同一設計の静的版で，Regular / Bold / Heavy を実体として
持っているため太字が正しく出る。`flake.nix` で `source-han-serif` /
`source-han-sans` を入れ，`TYPST_FONT_PATHS` で Typst に直接教えている
（fontconfig 任せにすると可変フォント版を拾ってしまう）。

なお js の既定フォントは原ノ味（Harano Aji）だが nixpkgs に無いため，その元となった
Source Han を指定している（同一設計なので見え方はほぼ変わらない）。

### js パッケージの取得について

`@preview/js:0.1.3` は初回のビルド時にネットワークから取得され，以降は
`~/.cache/typst` に残る。オフラインで初回ビルドはできない。

### その他

- 日本語見出しから生成される Typst のラベルが不正になるため，pandoc は
  `-f markdown-auto_identifiers` で呼んでいる（`Makefile` 参照）。
