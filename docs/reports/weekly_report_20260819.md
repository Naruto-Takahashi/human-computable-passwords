# 前提知識（研究全体の背景・用語・扱っている関数）

この報告書単体で内容を追えるよう，研究の枠組みと，本文中に登場する関数の定義をまとめる（過去の報告と重複するが再掲する）。

## 研究の枠組み

HCP（人間計算可能パスワード）とは，ユーザーが記憶する秘密の数表（以下「鍵」，各要素は0〜9の整数）と，暗算できる程度の簡単なアルゴリズムを使い，ランダムな入力（チャレンジ）から出力（レスポンス）を計算する認証方式である。本研究では，この「鍵をLLMがどこまで当てられるか／使いこなせるか」を測定するベンチマークとして再定義して扱っている。鍵と乱数シードから未知の問題を無限に生成できるため，事前学習データに答えが混入していないという利点がある。

研究は2つの経路で進めている：

経路A（in-context推論）：LLMの重みは一切更新せず，プロンプトの中にいくつかの入出力example（チャレンジ→レスポンスの組）を見せて，その場で鍵を推論・逆算させる。卒研計画の主軸。

経路B（ファインチューニング）：大量の入出力ペアを使い，追加学習（QLoRA）でLLMの重みに鍵とその使い方を覚え込ませる。従来の機械学習モデル（CNN）と同じ枠組みで，研究室の先行研究と直接比較できる。7月に一区切りとしたが，8月のご指示を受けて「深さ」という新しい軸で再開している。

## 記号の定義（原論文の記法）

**秘密写像 σ**（＝本報告で「鍵」と呼んでいるもの）

```
σ : [n] → Z₁₀
```

`[n]` は 1 から n までの自然数の集合 {1, 2, …, n}，`Z₁₀` は10で割った余りの同値類，すなわち1桁の整数の集合 {0, 1, …, 9} である。つまり σ は，画像や文字など n 個のオブジェクトから10進数の数字への写像であり，ユーザーはこれを暗記する。

**チャレンジ C**

```
Cᵢ ∈ [n]ᵏ
```

`Cᵢ` は i 番目のチャレンジ，`[n]ᵏ` は集合 `[n]` の直積を k 回とったもの，すなわち `[n]` の要素を並べた長さ k の列の全体である。

ここでの k は「1回のチャレンジで提示するオブジェクトの個数」＝チャレンジ長であり，関数 f が受け取る入力の個数と一致する（原論文は一般形を `f : Z₁₀^k → Z₁₀` と書く）。**この k は，後述する関数族のパラメータ k₁・k₂ とは別のものである**。両者には `k = 10 + k₁ + k₂` という関係がある。

**レスポンス**

```
f(σ(C))
```

`σ(C)` は，チャレンジ `C = (C₁, C₂, …, C_k)` の各要素に秘密写像 σ を適用したもの，すなわち `(σ(C₁), σ(C₂), …, σ(C_k))` である。サーバは公開されたチャレンジを提示し，ユーザーは暗記した σ で数字に直してから関数 f を暗算し，その結果を答える。

**本研究のパラメータと原論文の設定の対応**（今週，原文で確認した）

| | 本研究 | 原論文 |
| :-: | :-: | :-: |
| n（σ のマス数） | 26 | 説明用の例示として n=26 を挙げるが，実験・公開チャレンジの主軸は n=50・100。著者自身は n=100 を約2時間で暗記したと報告 |
| k（チャレンジ長） | 14 | 14（`f_{k₁,k₂}` の入力変数は `10+k₁+k₂` 個。`(k₁,k₂)` が (1,3)(2,2)(3,1) のいずれでも14で揃う） |

プログラム中の `sgm` が σ，`X[i]` が `Cᵢ` にあたる。n と k は独立なパラメータであり，n=26 と k=14 に直接の関係はない。

なお原論文は n=26 を**安全性が不十分**と明示している（"the value n = 26 is too small to provide UF-RCA security even with small values of m"）。CSPソルバー攻撃（f₂₂）の結果は次の通りで，n=26 は全条件で破られている。

| n | m=50 | m=100 | m=1000 | m=10000 |
| :-: | :-: | :-: | :-: | :-: |
| 26 | 23.5時間 | 40分 | 10分 | 2分 |
| 30 | HARD | UNSOLVED | 10分 | 20秒 |
| 50 | HARD | HARD | UNSOLVED | 7時間 |
| 100 | HARD | HARD | HARD | UNSOLVED |

したがって本研究が n=26 を用いる理由は「安全な設定を再現するため」ではなく，**LLMの能力を測るベンチマークとして適切な難易度水準を選んだため**である。この区別は卒論で明記する必要がある。なお n を大きくすると σ の暗記負荷が上がるため，安全性と可用性は原理的にトレードオフの関係にある。

**Stage（情報開示レベル）**：本研究で設けた実験条件。0=ヒントなし，1=σ開示・ルール非開示，2=ルール（関数 f）は開示するが σ は非開示，3=ルール開示＋σの一部を開示。本研究は主にStage 2で行っている。これは原論文の攻撃者モデル（f は既知，σ のみ未知）と一致する。

## 人間計算可能関数 f_{k₁,k₂}

原論文が提案する関数族は次の形をしている。

```
f_{k₁,k₂}(x₀, x₁, …, x_{9+k₁+k₂})  =  x_j + Σ[i=10+k₁ … 9+k₁+k₂] xᵢ   (mod 10)

              ここで   j  =  ( Σ[i=10 … 9+k₁] xᵢ )   (mod 10)
```

入力変数は `10 + k₁ + k₂` 個＝チャレンジ長 k である。入力ベクトルは `x = (σ(C₀), …, σ(C_{9+k₁+k₂}))`，すなわちチャレンジに σ を適用した後の数字列である。k₁ 個の項を足して添字 j を作り（＝どこを見るかを決める），参照した値 x_j にさらに k₂ 個の項を足して答えとする。先頭の10個（x₀〜x₉）は動的参照の飛び先として確保される（j が mod 10 で決まるため）。

本研究の主対象 `func_22` は `(k₁, k₂) = (2, 2)` の場合にあたる。

## 安全性パラメータ s(f)

原論文は，攻撃者が σ を復元するのに必要な観測数が `m = Ω̃(n^s(f))` であると示しており，その指数 s(f) を次のように定義している。

```
s(f) = min{ r(f)/2 ,  g(f)+1 }
```

r(f) は**分布的複雑度**，すなわち出力に偏り（相関）を生じさせないために固定しなければならない最小の入力変数数であり，提案関数では `r(f_{k₁,k₂}) = k₂ + 1` である。g(f) は**線形化変数数**，すなわち完全な線形方程式に退化させるために固定しなければならない最小の入力変数数であり，`g(f_{k₁,k₂}) = min{k₁, 10}` である。これを代入すると

```
s(f_{k₁,k₂}) = min{ (k₂+1)/2 ,  k₁+1 ,  11 }
```

となり，`func_22` では s(f) = 1.5 である。

この r(f) の定義「出力に偏りを生じさせないために固定すべき変数数」が `k₂+1` であることは，**最後の加算項 k₂ が出力分布の偏りを打ち消す役割を担っている**ことを意味する。今週見つけた2つの現象——足し算のない関数（k₂=0）では鍵の数字の偏りがそのまま答えの偏りになること，および不動点に落ちたとき足し算があれば答えが自明化しないこと——は，いずれもこの r(f) の構造が具体的に現れたものと理解できる。

## 難易度の分解と，扱っている関数の定義

本命の関数 `func_22` の難しさを3要素に分解し，簡単な要素から単独で検証できるよう診断用の関数を作成している。`sgm[i]` は鍵の i 番目，`X[i]` はチャレンジの i 番目を表す。

| 名称 | 計算式 | 検証する要素 |
| :-: | :-: | :-: |
| lookup\_k | Z = sgm\[X0\] | ①記憶：表を正しく参照できるか |
| table\_add\_k | Z = (sgm\[X0\] + sgm\[X1\]) mod 10 | ①+②合成：2箇所参照して足す |
| pointer\_k | j = (sgm\[X10\]+sgm\[X11\]) mod 10 ; Z = sgm\[X\[j\]\] | ③動的参照のみを単独抽出 |
| func\_22（本命） | j = (sgm\[X10\]+sgm\[X11\]) mod 10 ; Z = (sgm\[X\[j\]\] + sgm\[X12\] + sgm\[X13\]) mod 10 | ①+②+③すべて |

「動的参照」とは，計算の途中で求めた数値 j を使ってチャレンジの j 番目の要素を新たに読みに行き，その値をさらに鍵で変換する，という間接参照の構造を指す。今週の報告に出てくる `pointer_chain` は，この参照を繰り返して「深さ」を振れるようにしたものである。

# 今週の結果

## 評価方法に誤りがあり，先週までの結論が覆った

深さ1・2・3を比較する実験を行い，当初「深さの効果は確認できない」と結論していた。しかし**評価の件数が50件では粗すぎた**ことに気づいた。50件では約27ポイント以上の差しか検出できず，深さ間で見ていた差（12〜18ポイント）は原理的に判定不能だったためである。

評価にかかる時間は50件で82秒（学習は約2時間）と，学習の90分の1でしかない。そこで学習済みモデル8個を**再学習なしで500件で評価し直した**ところ，結論が変わった。

**評価件数500件での正解率**

| 鍵 | 深さ1 | 深さ2 | 深さ3 |
| :-: | :-: | :-: | :-: |
| 鍵A | 24.8% | 24.2% | **31.6%** |
| 鍵B | 35.8% | 35.6% | **44.0%** |

深さ1と深さ2は両方の鍵でほぼ完全に一致し（差は0.6ポイント以内，有意差なし），深さ3だけが両方の鍵とも約8ポイント高い（両鍵をまとめた検定で p < 0.001）。50件で測っていたときは点推定が最大13ポイントずれており，「2つの鍵で挙動が逆方向」という見かけ上の矛盾が生じていた。正しく測ると，独立した2つの鍵で同じ現象が再現している。

なお**方向は当初の予測とは逆**である。「深さが増すほど劣化する」ではなく「深さ3で上昇」した。

## 原因は関数設計の欠陥だった（不動点）

なぜ深いほど簡単になるのかを調べ，原因を特定した。

この関数は `j ← 鍵[X_j]` という参照を繰り返す。ここで **`鍵[X_j]` がたまたま j 自身と同じ値になると，ポインタはそこから動けなくなる**（不動点）。そしてこのとき `答え = 鍵[X_j] = j` となり，**答えがポインタの値そのものに一致する**という自明な関係に退化する。実データで確認したところ，停止した事例の**100%（216件中216件）**がこの関係を満たしていた。

反復を重ねるほどこの状態に捕まる確率は上がる（鍵Bでは深さ2の10%から深さ3の25%へ）。つまり**深さは難易度を単調に上げる変数として機能しておらず，むしろ自明な問題を増やしていた**。

さらに検証したところ，次のことが分かった。

不動点の**発生確率は足し算を加えても変わらない**（26.1%→26.1%）。有限集合の上で写像を反復すれば必ず循環に入るため，数学的に避けられない。ただし足し算があると，不動点に落ちても答えは自明にならない（自明化率100%→12.8%）。つまり**足し算は不動点の発生を防ぐのではなく，落ちても問題が壊れないよう保護する働き**をしている。これは前述の r(f) = k₂+1 という構造の，もう一つの現れ方だと理解できる。

真の原因は「**同じ写像を反復していること**」だった。一度止まると100%抜けられないためである。各ステップで異なる入力を使う設計（`j ← (鍵[X_j] + 鍵[X_{10+t}]) mod 10`）にすれば抜けられるようになり，深さを増やしても自明な事例は増えない（12%で頭打ち）。

**深さで難易度を制御するには，各ステップで新しい入力を使う必要がある**——これが今週得られた設計上の知見である。C案（深さラダーをin-contextで測る）を採る場合は，この修正を先に行う必要がある。

## 文献3本を読んだ

**小川さんの将来課題（5.4節）の正確な位置づけ**：同論文は「attentionベース・Transformer型モデルの評価が特に重要な次の一歩」とし，続けて大規模な事前学習済み・ファインチューニング済みモデルやdecoder-onlyモデルにも言及している。ただしその目的は一貫して *"baselines for learning f∘σ from leaked challenge-response pairs"*（漏洩ペアから応答予測器を学習するためのベースライン）と書かれており，`in-context` / `prompt` / `few-shot` / 重み凍結 といった語は本文に一度も現れない。さらに脅威モデル（3.1節）には *"The attacker's goal is not to recover σ explicitly"* と明記され，鍵の復元はニューラル攻撃の目標から外されている。

つまり小川さんが挙げた将来課題は，字義通りには経路B（教師あり学習）をより大きなモデルへ拡張するものである。経路Aは，アーキテクチャではなく**学習の与え方（重みを更新しない）と目標（鍵そのものを復元する）の両方**を変える点で，先行研究が想定していない設定にあたる。

# 8月の作業をどう位置づけるか

深さラダーの作業は，当初の狙い（深さが増すほど学習性能が劣化することの確認）は達成できなかったが，**「測定器を疑う」という方法論的な知見**を残した。

1. 足し算のない関数では，鍵の数字の偏りがそのまま答えの偏りになる（→ 適切な基準線の設定が必要）
2. 反復する参照は不動点を生み，深いほど問題が自明化する（→ 関数設計の必要条件）
3. 評価50件では点推定が最大13ポイントずれる（→ 今後は500件を標準とする）

いずれも経路Aの実験設計にそのまま効く教訓であり，どの案を採るにしても無駄にはならないと考えている。特に3点目は，今後のすべての実験の信頼性に関わる。
