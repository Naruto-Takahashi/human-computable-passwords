# この報告の要旨

前回（9月13日）の報告以降，2週間で実験を4つ実施した。

1. **実験12**：素朴な測定手順がどれだけ誤判定を出すかを測った（偽陰性の再現率）。
2. **実験13**：鍵が一意に定まる最小観測数 $m^*_{\text{info}}$ を確定し，経路Aの基準線を作った。
3. **予備実験A1pre**：in-context 推論の測定系を立ち上げ，測定欠陥を8つ潰した。
4. **実験C1**：**新設した経路C**（1から学習する Transformer）で，先行研究の中心的結論を検証した。

以下は結論の先出しである。用語と関数の定義は末尾の付録に記す。

## 何が分かったか

**① $j$ 項の壁は self-attention で消える。** $N=26$・50,000件の $f_{2,2}$ で
検証 1.0000・試験 0.9998（held-out 5,000件）。訓練と検証が同時に上がっており，
丸暗記ではない。漏洩・配管の不具合でないことを4通りの検査で確認した（2.5節）。

**② 難しさは理論指標 $s(f)$ の逆順である。** 離陸率は $f_{3,1}$（$s=1.0$）4/20
＜ $f_{1,3}$（$s=2.0$）11/20 ＜ $f_{2,2}$（$s=1.5$）15/20。理論上いちばん弱い
関数がいちばん破れにくい。

**③ 離陸するかは鍵で決まる。** 鍵5本 × 初期値4通りに分解すると，$f_{3,1}$ では
鍵が分散の100%，$f_{1,3}$ では85%を説明する。離陸しない鍵はどの初期値でも
0.28 前後に張り付く（基準線 0.11〜0.14）。

**④ 崩壊点は観測密度にある。** 鍵サイズを 26 → 50 にすると $f_{2,2}$ の離陸率は
15/20 → 3/20 に落ちる（統制は 20/20 → 16/20）。データ量にも閾値があり，
$j$ 項ありは 10,000件では全条件 0/20 で，50,000件で初めて離陸する。

**⑤ $j$ 項ありの方が情報的には「有利」である。** 鍵が一意に定まる最小観測数は
$j$ 項ありが最小（1観測が鍵5マスを制約するため）。したがって
「$j$ 項ありが失敗した」を情報不足では説明できない（3節）。

## 研究の位置づけがどう変わるか

研究室の系譜は 村田（MLP）→ 丸野（LSTM）→ 池田（埋め込み＋Bi-LSTM）→
小川（埋め込み＋CNN）と続いている。本研究はその5代目として
**Transformer エンコーダ**を置く。経路A（in-context）・経路B（追加学習）は
事前学習という交絡を持ち込むが，**経路C は先行研究との差分が self-attention
だけ**になるため，アーキテクチャの効果だけを取り出せる。

# 今回の結果

## 経路C を新設した理由

先行研究と本研究の学習器を3つの軸で分解すると，空いている枠が1つあった。

| 経路 | self-attention | 事前学習 | 重み更新 |
| :--------------------------- | :-----: | :-----: | :-----: |
| 先行研究（MLP / LSTM / CNN） | ✗ | ✗ | ✓ |
| **C（今回新設）** | **✓** | ✗ | ✓ |
| B（Qwen2.5-3B ＋ QLoRA） | ✓ | ✓ | ✓ |
| A（Qwen3.5 ＋ in-context） | ✓ | ✓ | ✗ |

: 学習器の3分解。経路C だけが先行研究との差分を self-attention に限定できる

小川ら §5.2 は「CNN は入力依存の添字から $x_j$ を選ぶという記号的操作を明示的に
実装していない。したがって attention 系・Transformer 系のモデルが自然な次の
ベースラインである。**今回それらを含めなかったのは，網羅的な構造探索が目的では
なかったためである**」と述べている。経路C はこの空白に対応する。

構成は次のとおりで，いずれも予備実験で選んだ（2.4節）。

1. **埋め込み**：画像ID（$0$〜$N-1$）を32次元の学習可能ベクトルに写す。
2. **位置埋め込み**：学習可能。位置情報を足さないと「10番目の値」と「12番目の値」を
   区別できない。
3. **エンコーダ2層**：多頭注意（4頭）→ 残差 → 層正規化 → 位置ごとの全結合。
   因果マスクは使わない（双方向）。
4. **読み出し**：先頭に置いた学習可能な1トークン（CLS）の出力だけを使う。
5. **分類頭**：全結合 → 10クラス softmax。

パラメータ数は約2万で，小川らの CNN（28,006）と同程度である。

## $j$ 項ありが解けた

$N=26$・50,000件・100エポック，鍵5本 × 初期値4通り = 20 run。

報告する量を先に定める。**先行研究と同じ定義に揃えてある。**

1. **正解率**：1桁のレスポンスを当てる10クラス分類の正解率。1 run につき
   **学習中の検証正解率の最大値**を記録し（小川ら §3.3 と同じ定義），
   その 20 run 分の平均と標準偏差を「平均 $\pm$ 標準偏差」として載せる。
2. **離陸率**：20 run のうち，上記が 0.5 を超えた run の割合。
3. **試験正解率**：訓練にも検証にも使っていない held-out 集合（全体の10%）での
   正解率。検証正解率が最良だったエポックの重みで測る。

1 は検証集合の上で最大値を選ぶため楽観側に振れる。したがって 3 を併記する。
実際には両者はほぼ一致した（下表の $f_{2,2}$ で 0.7710 対 0.7709）。
なお小川らは訓練:検証 = 8:2 で**試験集合を持たない**ため，比較できるのは 1 である。

## 難しさは $s(f)$ の逆順である

原論文（Blocki ら 2017）の安全性パラメータは
$s(f_{k_1,k_2}) = \min\{(k_2+1)/2,\ k_1+1\}$ で，統計的攻撃者が鍵を復元するには
$m = \tilde{\Omega}(n^{s(f)})$ の観測を要する。理論上は $f_{1,3}$（2.0）が最も安全で
$f_{3,1}$（1.0）が最も弱い。

観測された離陸率は逆である。**理論上いちばん弱い $f_{3,1}$ がいちばん破れにくい**
（4/20）。小川らも「best observed accuracies do not align monotonically with
$s(f)$」と述べていたが，離陸率で測ると非単調どころか逆順になる。

$s(f)$ は統計的攻撃者の標本複雑度の下界であり，勾配学習の離陸しやすさとは
別の量である，と整理するのが妥当と考えている。

## 離陸するかは鍵で決まる

20 run を「鍵5本 × 初期値4通り」の表に組み直し，ばらつきを分解した。

| 関数 | 鍵 | 初期値 | 交互作用・残差 | 形 |
| :--------- | :---: | :---: | :---: | :------------------------------------ |
| $f_{3,1}$ | **100%** | 0% | 0% | 鍵1本だけが離陸。他はどの初期値でも 0.28〜0.32 |
| $f_{1,3}$ | **85%** | 3% | 12% | 鍵ごとに 1.0000 か 0.10 の二値 |
| $f_{2,2}$ | 27% | 25% | 48% | 鍵と初期値が同程度。交互作用が最大 |
| $h$（統制） | — | — | — | 20/20 すべて 1.0000（ばらつきなし） |

: 離陸のばらつきの内訳（$N=26$・50,000件）

**この分解ができたのは，鍵の乱数シードと重み初期化の乱数シードを分けたためである。**
分ける前は離陸した run のシードが2つに偏っており，「この鍵が易しい」のか
「この初期値が当たり」なのかを切り分けられなかった。8月以降の報告で
「鍵の効果」を主張しては撤回してきた問題が，ここで解消した。

何が鍵を破れやすくするかは未解決だが，手がかりがある。

| 鍵 | 異なる数字 | 最多重複 | エントロピー | $f_{1,3}$ | $f_{2,2}$ | $f_{3,1}$ |
| :--- | :-----: | :----: | :--------------: | :---: | :---: | :---: |
| 鍵1 | 8 | 8 | **2.767** | 4/4 | 4/4 | **4/4** |
| 鍵2 | 9 | 5 | 3.042 | 0/4 | 2/4 | 0/4 |
| 鍵3 | 9 | 6 | 2.874 | 4/4 | 3/4 | 0/4 |
| 鍵4 | 10 | 5 | 3.071 | 3/4 | 4/4 | 0/4 |
| 鍵5 | 10 | 4 | **3.181** | 0/4 | 2/4 | 0/4 |

: 鍵の数字分布と離陸（4初期値中の離陸数）

$f_{3,1}$ が離陸した唯一の鍵は，最もエントロピーが低い。$f_{3,1}$ は $k_2=1$ で
末尾の足し算が1項しかないため，**鍵の偏りが出力に漏れやすい**。これは原論文の
$r(f) = k_2+1$ の直観（足す項が少ないほど出力を偏らせられる）と整合する。
ただし鍵5本での観察なので，仮説として扱っている。

## 崩壊点は観測密度にある

| 関数 | $N$ | 1,000 | 5,000 | 10,000 | 50,000 |
| :--------------- | :---: | :---: | :---: | :---: | :---: |
| $h$（統制） | 26 | 0/5 | 0/5 | **10/20** | **20/20** |
| $f_{2,2}$ | 26 | 0/5 | 0/5 | 0/20 | **15/20** |
| $f_{1,3}$ | 26 | 0/5 | 0/5 | 0/20 | **11/20** |
| $f_{3,1}$ | 26 | 0/5 | 0/5 | 0/20 | **4/20** |
| $h$（統制） | 50 | 0/5 | 0/5 | 4/20 | **16/20** |
| $f_{2,2}$ | 50 | 0/5 | 0/5 | 0/20 | **3/20** |
| $f_{1,3}$ | 50 | 0/5 | 0/5 | 0/20 | **1/20** |
| $f_{3,1}$ | 50 | 0/5 | 0/5 | 0/20 | **0/20** |

: 鍵サイズとデータ量による離陸率（400 run）

読み取れることが2つある。

1. **鍵サイズ 50 が崩壊点になる。** $j$ 項ありは 15/20 → 3/20 に落ちるが，統制は
   20/20 → 16/20 しか落ちない。$j$ 項の分だけ観測密度への要求が高い。
2. **$j$ 項ありは 10,000件では一度も離陸しない**（両方の鍵サイズで 0/20）。
   統制は 10,000件で 10/20 なので，$j$ 項があるとデータ量の閾値が上がる。

なお $f_{3,1}$ は $N=50$ で 0/20 だが，平均は $0.2732 \pm 0.0088$ で基準線
（0.115）を大きく上回り，**ばらつきが極端に小さい**。部分的な構造は安定して
学習できており，$x_j$ の参照に届いていない状態と読める。

## 1.0000 が本物であることを確かめた

正解率 1.0 は疑うべき数値なので，疑う点を4つ挙げて別のスクリプトで潰した。

| 疑い | 確認方法 | 結果 |
| :---------------------------- | :----------------------------- | :------- |
| 訓練とテストに同じ問題が出ている | 別の乱数で引いた10,000件との重複を数える | **0 件** |
| 分割のコードが 1.0 を作っている | **新しく引いた10,000件**で測る | **0.9911** |
| 配管が 1.0 を作っている | ラベルをシャッフルした対照 | 訓練 0.1115 / 検証 0.1094 |
| 本当に鍵を学習したのか | 各マスを位置0に固定した $200 \times 26$ 件 | **0.9906** |

: 検証の4点（$d_{model}=32$・CLS 読み出し・120エポック）

3つめが決定的である。同じ配管・同じモデル・同じデータでラベルだけ潰すと，
**訓練精度すら 0.11 に落ちる**。2つめは分割を一切通さない新規チャレンジでの
値なので，漏洩でもない。

# 経路A の基準線を作った（実験13）

経路C とは別に，in-context 推論（経路A）の基準線を整備した。**鍵が一意に定まる
最小観測数** $m^*_{\text{info}}$ を，専用のソルバーで全探索して確定した。

| 鍵サイズ $n$ | $j$ 項あり | 統制（静的3項） | 統制（文面のみ動的） |
| :---: | :---: | :---: | :---: |
| 4 | 5.0（**1.30n**） | 5.0（1.37n） | 5.0（1.48n） |
| 6 | 7.0（**1.22n**） | 8.0（1.46n） | 8.0（1.39n） |
| 8 | 9.0（**1.23n**） | 10.0（1.45n） | 10.0（1.24n） |
| 10 | 11.0（**1.13n**） | 13.0（1.42n） | 12.0（1.25n） |
| 13 | 14.0（**1.14n**） | 17.0（1.42n） | 16.0（1.37n） |

: $m^*_{\text{info}}$ の中央値（鍵5本 × 観測の引き3通り）。括弧内は $m^*/n$ の平均

**5つの鍵サイズすべてで $j$ 項ありが最小である。** 機構は1観測が制約する鍵マス数の
違いにある。$j$ 項ありは和の3マスに加えて添字を作る2マスを制約するので5マス，
統制は3マスである。

この事実には使い道がある。**$j$ 項ありが失敗したとき，それを情報不足では説明
できない。** 先行研究は条件ごとの基準線を持たないため，この切り分けができなかった。

$m^*_{\text{info}}$ は $n$ に比例し（$m^*/n \approx 1.1$〜$1.5$），安全性パラメータ
$s(f)$ には依存しない（Friedman 検定で $p = 0.068$）。これは $s(f)$ が
**統計的攻撃者**の標本複雑度を述べたものであり，全探索ソルバーの情報量下限とは
別の量だからである。当初「$m^* \propto \ln n$ ではないか」と考えたが，
3つの鍵サイズで測って否定した。

副産物として，ソルバーの探索を **約540倍**高速化した（無影響な鍵マスを事前に
検出して探索から外す）。`narrowptr_k26_m1`・$m=40$ で 213,122ノード・12.5秒が
395ノード・0.15秒になり，過去の 1,983件の計数がすべて再現することを確認した。
これにより鍵サイズ26の基準線も測れるようになった。

# 測定系の不具合を8つ潰した（予備実験A1pre）

in-context 推論の測定系を立ち上げる過程で，**成功しているのに失敗と記録される**
不具合を8つ見つけて修正した。代表的なものを挙げる。

1. **推論内容が別のチャネルに出ていた。** 使用したモデルは本文を思考チャネルへ
   書くため，回答欄が空に見えていた。
2. **生成が上限で打ち切られていた。** 打ち切りを「不正解」と記録していた。
   打ち切り率を指標に加えた。
3. **拒否判定の語が正答を飲み込んでいた。** `unknown` を拒否語として扱っていたため，
   `{"answer": 8}` という正答が拒否と判定されていた。
4. **記法が関数の族ごとに逆だった。** ある族では $X$ が入力値，別の族では変換後の値を
   指していた。さらに注意書きの中で散文と括弧内が食い違っており，モデルが
   「この記述は矛盾しています」と述べて答えに到達する前に生成上限へ達していた。

4つめの修正は効果が明確だった。記法を統一した前後で，同じ関数・同じ鍵が

# 付録：前提知識（研究全体の背景・用語・扱っている関数）

この報告書単体で内容を追えるよう，研究の枠組みと本文中に登場する関数の定義をまとめる（過去の報告と重複するが再掲する）。

## 研究の枠組み

HCP（人間計算可能パスワード）とは，ユーザーが記憶する秘密の数表（以下「鍵」，各要素は0〜9の整数）と，暗算できる程度の簡単なアルゴリズムを使い，ランダムな入力（チャレンジ）から出力（レスポンス）を計算する認証方式である。本研究では，この「鍵をLLMがどこまで当てられるか／使いこなせるか」を測定するベンチマークとして再定義して扱っている。鍵と乱数シードから未知の問題を無限に生成できるため，事前学習データに答えが混入していないという利点がある。

研究は3つの経路で進めている：

1. 経路A（in-context推論）：LLMの重みは一切更新せず，プロンプトの中にいくつかの入出力example（チャレンジ→レスポンスの組）を見せて，その場で鍵を推論・逆算させる。

2. 経路B（ファインチューニング）：大量の入出力ペアを使い，追加学習（QLoRA）でLLMの重みに鍵とその使い方を覚え込ませる。従来の機械学習モデル（CNN）と同じ枠組みで，研究室の先行研究と直接比較できる。7月に一区切りとしたが，8月の指導教員の指示「より難しい関数の探索」を受けて再開している。

3. 経路C（1から学習する Transformer）：事前学習を持たない小さな Transformer エンコーダを，先行研究の CNN と同じデータ・同じ評価で学習させる。**先行研究との差分が self-attention だけになる**ため，アーキテクチャの効果だけを取り出せる。2026年9月に着手した。

3つの関係は次節の表に整理した。

## 実験の基本設定

1. **モデル**：ローカルで動かせる Qwen2.5-3B-Instruct を用い，QLoRA（4bit量子化＋LoRA）で追加学習している。

2. **Bパラダイム**：経路Bで採用している学習・評価形式。プロンプトはFew-shot例を含まない最小形式（「Input: [...] に対する Z を答えよ」のみ）とし，従来のCNNと同じ「入力→出力の直接対応のみを学習する」条件に揃えている。

3. **paradigm=pure**：教師データの形式。学習の答え（教師completion）は `{"answer": <値>}` というJSON1行のみで，計算の途中経過や鍵の値は一切含まない。損失もこの1行にしかかからず，プロンプト側（ルールの説明文を含む）には一切かからない。

4. **held-out評価**：学習に使ったデータとは別に生成した，一度も見せていない入力で正解率を測定する。学習用と評価用でチャレンジの乱数シード空間を分離しており，重複しないことを保証している。

5. **学習条件**：学習1000件・5エポックを標準としている（1000件という数は，比較対象であるCNNの学習データ量に揃えたもの）。

## 記号の定義（原論文の記法）

### 秘密写像 σ（＝本研究で「鍵」と呼んでいるもの）

$$
\sigma : [n] \to \mathbb{Z}_{10}
$$

$[n]$ は $1$ から $n$ までの自然数の集合 $\{1, 2, \dots, n\}$，$\mathbb{Z}_{10}$ は10で割った余りの同値類，すなわち1桁の整数の集合 $\{0, 1, \dots, 9\}$ である。つまり $\sigma$ は，画像や文字など n 個のオブジェクトから10進数の数字への写像であり，ユーザーはこれを暗記する。

### チャレンジ C

$$
C_i \in [n]^k
$$

$C_i$ は $i$ 番目のチャレンジ，$[n]^k$ は集合 $[n]$ の直積を $k$ 回とったもの，すなわち $[n]$ の要素を並べた長さ $k$ の列の全体である。

ここでの $k$ は「1回のチャレンジで提示するオブジェクトの個数」＝チャレンジ長であり，関数 $f$ が受け取る入力の個数と一致する（原論文は一般形を $f : \mathbb{Z}_{10}^k \to \mathbb{Z}_{10}$ と書く）。**この $k$ は，後述する関数族のパラメータ $k_1$・$k_2$ とは別のものである**。両者には $k = 10 + k_1 + k_2$ という関係がある。

### レスポンス

$$
f(\sigma(C))
$$

$\sigma(C)$ は，チャレンジ $C = (C_1, C_2, \dots, C_k)$ の各要素に秘密写像 $\sigma$ を適用したもの，すなわち $(\sigma(C_1), \sigma(C_2), \dots, \sigma(C_k))$ である。サーバは公開されたチャレンジを提示し，ユーザーは暗記した $\sigma$ で数字に直してから関数 $f$ を暗算し，その結果を答える。

## 本研究のパラメータと原論文の設定の対応

原論文で確認した内容である（2026-08）。

**本研究のパラメータと原論文の設定の対応**


| | 本研究 | 原論文 |
| :--------------- | :-----------: | :------------------------------------ |
| $n$（$\sigma$ のマス数） | 10 または 26 | 説明用の例示として n=26 を挙げるが，実験・公開チャレンジの主軸は n=50・100。著者自身は n=100 を約2時間で暗記したと報告 |

なお原論文は n=26 を**安全性が不十分**と明示している（"the value n = 26 is too small to provide UF-RCA security even with small values of m"）。CSPソルバー攻撃（$f_{22}$）の結果は次の通りで，n=26 は全条件で破られている。

| 30 | HARD | UNSOLVED | 10分 | 20秒 |

**Stage（情報開示レベル）**：0=ヒントなし，1=$\sigma$開示・ルール非開示，2=ルール（関数 $f$）は開示するが $\sigma$ は非開示，3=ルール開示＋$\sigma$の一部を開示。本研究は主にStage 2で行っている。

## 人間計算可能関数 $f_{k_1,k_2}$

原論文が提案する関数族は次の形をしている。

$$f_{k_1,k_2}(x_0, x_1, \dots, x_{9+k_1+k_2})
   = x_j + \sum_{i=10+k_1}^{9+k_1+k_2} x_i \pmod{10}
$$

$$
\text{ここで}\quad j = \left( \sum_{i=10}^{9+k_1} x_i \right) \bmod 10
$$

入力変数は $10 + k_1 + k_2$ 個＝チャレンジ長 $k$ である。入力ベクトルは $x = (\sigma(C_0), \dots, \sigma(C_{9+k_1+k_2}))$，すなわちチャレンジに $\sigma$ を適用した後の数字列である。$k_1$ 個の項を足して添字 $j$ を作り（＝どこを見るかを決める），参照した値 $x_j$ にさらに $k_2$ 個の項を足して答えとする。先頭の10個（$x_0$〜$x_9$）は動的参照の飛び先として確保される（$j$ が $\bmod 10$ で決まるため）。

本研究の主対象 `func_22` は $(k_1, k_2) = (2, 2)$ の場合にあたる。

## 安全性パラメータ $s(f)$

原論文は，攻撃者が $\sigma$ を復元するのに必要な観測数が $m = \tilde{\Omega}(n^{s(f)})$ であると示しており，その指数 $s(f)$ を次のように定義している。

$$
s(f) = \min\left\{ \frac{r(f)}{2},\ g(f)+1 \right\}
$$

$r(f)$ は**分布的複雑度**，すなわち出力に偏り（相関）を生じさせないために固定しなければならない最小の入力変数数であり，提案関数では $r(f_{k_1,k_2}) = k_2 + 1$ である。$g(f)$ は**線形化変数数**，すなわち完全な線形方程式に退化させるために固定しなければならない最小の入力変数数であり，$g(f_{k_1,k_2}) = \min\{ k_1, 10\}$ である。これを代入すると

$$
s(f_{k_1,k_2}) = \min\left\{ \frac{k_2+1}{2},\ k_1+1,\ 11 \right\}
$$

となり，`func_22` では $s(f) = 1.5$ である。

この $r(f)$ の定義「出力に偏りを生じさせないために固定すべき変数数」が $k_2+1$ であることは，**最後の加算項 $k_2$ が出力分布の偏りを打ち消す役割を担っている**ことを意味する。実験2 の結果は，この構造が実際に効いていることを示している（experiment_index.md）。

## 難易度の分解と，扱っている関数の定義

本命の関数 `func_22` の難しさを3要素に分解し，簡単な要素から単独で検証できるよう診断用の関数を作成している。`sgm[i]` は鍵の i 番目，`X[i]` はチャレンジの i 番目を表す。

**難易度を3要素に分解した診断用の関数**


| 名称 | 計算式 | 分離している要素 |
| :--- | :--- | :--- |
| `lookup_k` | $Z = \text{sgm}[X_0]$ | ① 記憶のみ |
| `table_add_k` | $Z = (\text{sgm}[X_0] + \text{sgm}[X_1]) \bmod 10$ | ① + ② 合成 |
| `pointer_k` | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 10$<br>$Z = \text{sgm}[X_j]$ | ① + ③ 動的参照 |
| `func_22`（本命） | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 10$<br>$Z = (\text{sgm}[X_j] + \text{sgm}[X_{12}] + \text{sgm}[X_{13}]) \bmod 10$ | ① + ② + ③ |
| `table_add3_k` | $Z = (\text{sgm}[X_0] + \text{sgm}[X_1] + \text{sgm}[X_2]) \bmod 10$ | ① + ②（静的3項．統制） |
| `narrowptr_k_m1` | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 1 = 0$<br>$Z = (\text{sgm}[X_j] + \text{sgm}[X_{12}] + \text{sgm}[X_{13}]) \bmod 10$ | 文面は動的・実質静的（統制） |
| `func_pow` | $Z = (\text{sgm}[X_{10}]^4 + 2\,\text{sgm}[X_{11}]^3 + 3\,\text{sgm}[X_{12}]^2 + 4\,\text{sgm}[X_{13}]) \bmod 10$ | 小川ら Table 6 の no-j 統制そのもの |


「動的参照」とは，計算の途中で求めた数値 j を使ってチャレンジの j 番目の要素を新たに読みに行き，その値をさらに鍵で変換する，という間接参照の構造を指す。

## 8月の指示（動的参照の拡張）と，追加した関数

8月に指導教員から「人間計算可能性を少し犠牲にしても，動的参照構造を増やす方向でLLMの限界を探る」という指示があり，共有された資料（8/1）で挙げられていた候補のうち，優先度の高い3種類を実装した。いずれも本命の `func_22`（動的参照が1本）を出発点に，**動的参照の本数や繋ぎ方を変えた**ものである。

### pointer_chain（深さ方向・直列に反復）

$$\begin{aligned}
j &= (\text{鍵}[X_{10}] + \text{鍵}[X_{11}]) \bmod 10 \\
j &\leftarrow \text{鍵}[X_j]
   &&\text{… これを（深さ$-1$）回くりかえす} \\
Z &= \text{鍵}[X_j]
\end{aligned}
$$

同じ操作「指した先を見て，その値が示す位置をまた指す」を繰り返す。深さ1は既存の `pointer_k` と一致する。**足し算を含まない**（$k_2=0$）のは，深さの効果だけを取り出すためである。

### dualptr（並列・独立な2本）

$$\begin{aligned}
j_1 &= (\text{鍵}[X_{10}] + \text{鍵}[X_{11}]) \bmod 10 \\
j_2 &= (\text{鍵}[X_{12}] + \text{鍵}[X_{13}]) \bmod 10
     &&\text{… $j_1$ とは無関係に決まる} \\
Z   &= (\text{鍵}[X_{j_1}] + \text{鍵}[X_{j_2}]) \bmod 10
\end{aligned}
$$

動的参照を2本に増やすが，**互いに依存しない**。2箇所を別々に見に行って足す形なので，反復（前の結果を次の入力にする）は含まない。資料では「最大候補（私の本命）」と位置づけられていた。

### recptr（直列・依存あり）

$$\begin{aligned}
j_1 &= (\text{鍵}[X_{10}] + \text{鍵}[X_{11}]) \bmod 10 \\
j_2 &= (\text{鍵}[X_{j_1}] + \text{鍵}[X_{12}]) \bmod 10
     &&\text{… $j_1$ の参照結果が $j_2$ の計算に入る} \\
Z   &= (\text{鍵}[X_{j_2}] + \text{鍵}[X_{13}]) \bmod 10
\end{aligned}
$$

2本目のポインタ $j_2$ を求めるのに1本目の参照結果 $\text{鍵}[X_{j_1}]$ を使うため，**参照同士に依存関係がある**。`func_22` の依存を一段強めた形にあたる。`pointer_chain` と似ているが，**各段で新しい項（$X_{12}$，$X_{13}$）を足す**点が決定的に異なる（不動点に落ちない理由．experiment_index.md の実験2）。

**8月に追加した3つの関数の比較**


| 名称 | 動的参照の本数 | 参照どうしの関係 | 末尾の足し算 |
| :-------------- | :----------: | :--------------: | :----------: |
| func_22（基準） | 1本 | — | あり |
| pointer_chain | 深さ分（直列） | 前の結果が次の入力 | **なし** |
| dualptr | 2本 | 独立（依存なし） | あり |
| recptr | 2本 | 依存あり | あり |


3つとも実験済み（実験2・3）。

なお `dualptr`・`recptr` はいずれも末尾に足し算があり（$k_2 > 0$），足し算のない `pointer_chain`（$k_2 = 0$）とそのまま比べると「動的参照の構造」と「足し算の有無」が交絡する。そこで**動的参照1本＋足し算**の基準線として，`func_22` の鍵10マス版（`func_22_k10`）を用意した。`func_22` は本来 $n = 26$ だが，$n = 26$ では動的参照の有無に関わらず崩壊して差が見えないため（実験1），深さラダーと同じ $n = 10$ に揃えている。

## これまでの結果の要点（今回の報告の前提）

**7〜8月の結論の多くは撤回・保留になっている。**原因は関数の難しさではなく
測定系だった（9月13日の報告）。ここには現時点で保っている結論だけを書く。

### 測定について（経路B で判明したこと）

1. **正解率が偶然水準付近でも「学習できない」とは言えない。**与えた学習予算の中で
   学習が**離陸したか**を測っていた。同じ関数・同じ鍵でもデータの引き方を変えると
   10.2% が 100% になる。
2. **1条件1run では何も言えない。**離陸は run ごとに起きるか起きないかであり，
   平均±標準偏差はその混合比を報告しているにすぎない。**離陸率**で報告する。
3. **偶然水準（10%）と比べてはいけない。**鍵ごとの**最頻値基準線**と比べる。
4. **鍵を揃えずに関数を比べてはいけない。**「$n=10$ で動的参照の有無が 100% 対 34%」
   という7月の統制実験は鍵を揃えていない比較であり，撤回した。

### 関数と難しさについて

5. ①記憶と②合成は，十分なデータ量があれば学習できる（未知の組み合わせでも汎化する）。
6. **③動的参照（$j$ 項）は，self-attention を与えると解ける。**経路C で
   $N=26$・50,000件の $f_{2,2}$ が検証 1.0000・試験 0.9998 に達した。小川らの CNN は
   同条件で最大 0.6858・平均 0.2872 であり，**「$j$ 項が構造的な壁」という
   先行研究の中心的結論はアーキテクチャ依存の主張に弱まる**。
7. **難しさは理論指標 $s(f)$ の順に並ばない（むしろ逆順）。**離陸率は
   $f_{3,1}$（$s=1.0$）4/20 ＜ $f_{1,3}$（$s=2.0$）11/20 ＜ $f_{2,2}$（$s=1.5$）15/20。
8. **離陸するかは，多くの場合鍵 $\sigma$ そのものの性質で決まる。**鍵5本 × 初期値4通りに
   分解すると，$f_{3,1}$ では鍵が分散の 100%，$f_{1,3}$ では 85% を説明する。
9. **崩壊点は観測密度にある。**鍵サイズを 26 → 50 にすると $f_{2,2}$ の離陸率は
   15/20 → 3/20 に落ちる（統制は 20/20 → 16/20）。データ量も 10,000件では
   $j$ 項ありが全条件 0/20 で，50,000件で初めて離陸する。

### 情報量の下限について（経路A の基準線）

10. 鍵が一意に定まる最小観測数 $m^*_{\text{info}}$ は $n$ に**比例**する
    （$m^*/n \approx 1.1\text{〜}1.5$）。決めているのは1観測が制約する鍵マス数で，
    $s(f)$ には依らない。**$j$ 項ありの方が最小である**（1観測が5マスを制約するため）。
    したがって「$j$ 項ありが失敗した」を情報不足では説明できない。

## 用語（本研究で独自に使っているもの）

学習一般の用語（損失・エポック・LoRA など）は
`docs/llm_training_basics.md` の用語表にある．

| 用語 | 意味 |
|---|---|
| 鍵 / $\sigma$ | 利用者が記憶する秘密の数表．長さ $n$，各要素は 0〜9 |
| チャレンジ / $C$ | 認証のたびに提示される $k$ 個の位置の並び |
| レスポンス / $Z$ | チャレンジに対して暗算で返す1桁の数字 |
| 鍵シード（`key_seed`） | どの鍵を使うかを決める乱数シード |
| データシード（`data_seed`） | どのチャレンジを引くかを決める乱数シード．鍵は変えない |
| 衝突確率 | $\sum_i p_i^2$．答えの分布を完全に知った上で独立に当てずっぽうしたときの正解率．**偶然水準（10%）ではなくこれと比べる** |
| 最頻値基準線 | 最も多い答えを常に返す戦略の正解率．計算能力ゼロでも出る下限 |
| 離陸 | 学習が動き出し，検証損失が急に落ちること．本研究では検証損失 0.15 を下回った最初のエポックで判定する |
| 床 | 正解率が偶然水準付近に張り付き，条件間の差が識別できない状態 |
| 離陸率 | 同一条件を反復したうち離陸した run の割合．**経路C の主指標** |
| 初期化シード（`init_seed`） | 重みの初期値を決める乱数シード．鍵シードと分けて振る |
| $m^*_{\text{info}}$ | 鍵が一意に定まる最小観測数．情報量の下限 |
| 動的参照 | 参照する位置そのものを計算して決めること（$X_j$ の $j$ を入力から作る） |
| 静的参照 | 参照する位置が固定されていること（$X_0$, $X_{12}$ など） |
