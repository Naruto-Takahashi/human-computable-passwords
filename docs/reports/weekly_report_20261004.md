# この報告の要旨

前回（9月28日）の報告で，経路C（1から学習するTransformer）により $j$ 項の壁が
self-attentionで消えること，また離陸するかどうかが鍵 $\sigma$ の性質（多くの場合
分散の85〜100%）で決まることを示した。ただし鍵5本では「どんな鍵が破れやすいか」
まで踏み込めず，エントロピーとの相関は検出力不足で非有意だった。

今週は，その追試である**実験C2**（鍵20本）を実施した。

1. **本番前の見直し**：エポック予算（100）が十分か既存データで確認し，
   $f_{2,2}$ だけ初期値を2→4通りに増やした。
2. **並列実行の効率化**：CPU使用率を実測し，スレッド割当を見直した。
3. **実験C2の実施**：鍵20本×3関数＝160 runを完走。H-C2（$k_2$順の予測）は反証された。
4. **鍵の偏りの評価方法**：鍵の偏り指標（最多重複・エントロピー）が離陸率に
   効くかを，鍵ごとの基準線を統制して判定した。

以下は結論の先出しである。用語と関数の定義は末尾の付録に記す。

## 何が分かったか

**① 離陸率はC1（鍵5本）とほぼ再現した。** $f_{2,2}$ 69%（55/80）・$f_{1,3}$ 65%
（26/40）・$f_{3,1}$ 20%（8/40）。鍵を増やしても崩れていない。

**② H-C2は反証された。** エントロピーとの相関は $k_2$ の順（$f_{3,1} \gt f_{2,2}
\gt f_{1,3}$）には並ばず，$f_{2,2}$ だけが非有意（$p=0.099$）だった。
原論文の $r(f)=k_2+1$ から立てた機構は，この形では支持されない。

**③ 鍵の偏りの効果は，鍵ごとの基準線を統制して初めて判定できる。** 最多重複は
鍵ごとの基準線（最頻値予測器の正解率）自体と強く相関しており（$f_{3,1}$ で
$\rho=0.85$），固定しきい値による離陸判定だけを見ると，基準線のシフトを経由した
見かけの相関が混ざる。基準線を統制すると，$f_{3,1}$・$f_{1,3}$ では
**エントロピーの方が残る**。

**④ $f_{2,2}$ だけはどちらの指標でも説明できない。** 基準線統制後，エントロピー
（$p=0.523$）・最多重複（$p=0.209$）のいずれも非有意である。

**⑤ 離陸する鍵は「1本の例外」ではなかった。** C1では $f_{3,1}$ で離陸した鍵は
5本中1本だけだったが，鍵20本で見ると**5/20鍵**が部分的・完全に離陸した。

**⑥ CPU並列の設定を見直し，約1.4倍速くできることを確認した。** 1プロセスに
4スレッド割っても実際のCPU使用率は172%（1.7コア相当）にしかならず，
1プロセス1スレッドに分解したほうが同じコア数でより多くのrunを並行させられる。

# 今回の結果

## 実験C2を回す前に見直した2点

**エポック予算（100）の妥当性。** C1で $f_{3,1}$ が離陸しなかった4鍵の検証正解率
の履歴を読み直した。終盤10エポックで上昇の気配はなく（例：key_seed 20260928 は
ep10=0.284 → ep100=0.25 と**下降**），予算不足で打ち切っている様子はなかった。
新たな計算は増やさず，既存データの読み直しだけで確認できた。

**初期値の配分。** C1の分散分解で $f_{2,2}$ だけ交互作用が48%（鍵27%・初期値25%・
交互作用48%）と最大だった。初期値2通りのままでは $f_{2,2}$ の鍵ごとの離陸率の
点推定が粗くなるため，$f_{2,2}$ だけ初期値を4通りに増やした
（$f_{3,1}$・$f_{1,3}$ は鍵が分散の85〜100%を説明しており2通りで足りる）。

## CPU並列実行の効率化

8条件（$f_{3,1}$×2・$f_{1,3}$×2・$f_{2,2}$×4の初期値ブロック）を並列に流す
バッチスクリプトで，従来は1プロセスあたり4スレッド・5プロセス同時という設定を
使っていた。1 run を縮小実験（5エポック）で測ったところ，CPU使用率は**172%**
（1.7コア相当）にしかならず，4スレッドの大半が遊んでいた。

| 設定 | 20 run の所要（縮小実験） | CPU使用率 |
| :----------------------- | :--------------------: | :-------: |
| 5プロセス × 4スレッド（従来） | 182秒 | 852% |
| 10プロセス × 2スレッド | 145秒 | 1351% |
| **20プロセス × 1スレッド** | **131秒** | **1579%** |
| 30プロセス × 1スレッド（過剰占有） | 214秒（30 run） | 1764% |

: CPU 20コアでの並列度比較（`func_31`・5エポックの縮小実験）

モデルが小さすぎて複数スレッドの並列化が効かないため，**1プロセスに割るスレッド
を減らし，その分プロセス数を増やす方が速い**。20コアちょうど（20プロセス×1
スレッド）が頭打ちで，それを超える過剰占有（30プロセス）はむしろ悪化した。

ただし実際のバッチスクリプトは「1プロセスが鍵20本を逐次処理する」構造になって
おり，条件の本数（8本）を超えてプロセスを増やしても意味がない。細粒度に組み
直す改修まではせず，今回は**8条件を最初から同時に（JOBS=8），各プロセスは
スレッド2（THREADS=2）**という変更だけで実行した。

### H-C2の判定：$k_2$ 順の予測は反証された

> **H-C2**：鍵の数字分布の偏り（エントロピーの低さ）が離陸しやすさを決める。
> その効き方は $k_2$（末尾の加算項数）が小さいほど強い。
>
> **予測**：エントロピーと離陸率の相関が $f_{3,1}$（$k_2=1$）$\gt$ $f_{2,2}$
> （$k_2=2$）$\gt$ $f_{1,3}$（$k_2=3$）の順に強くなる。

| 関数 | $k_2$ | エントロピー相関 | 最多重複 相関 |
| :-------- | :---: | :--------------------: | :-------------------: |
| $f_{3,1}$ | 1 | $\rho=-0.69$，$p=0.001$ ** | $\rho=+0.64$，$p=0.003$ ** |
| $f_{2,2}$ | 2 | $\rho=-0.38$，$p=0.099$ | $\rho=+0.52$，$p=0.019$ * |
| $f_{1,3}$ | 3 | $\rho=-0.74$，$p=0.000$ *** | $\rho=+0.49$，$p=0.030$ * |

: 鍵の偏りと離陸率の素のSpearman相関（鍵20本，$N=26$・50,000件）

![鍵の最多重複と離陸率の散布図（3関数。この相関は次節で基準線の交絡を含むと分かった）](docs/reports/figures/c2_skew_correlation.svg)

エントロピーで見ると **$f_{1,3}$（$p=0.000$）$\approx$ $f_{3,1}$（$p=0.001$）
$\gg$ $f_{2,2}$（$p=0.099$，非有意）** という順であり，予測した $k_2$ の順には
全く並んでいない。**H-C2の反証条件（$k_2$ の順に並ばない）が成立した。**

### 鍵の偏りの効果は，鍵ごとの基準線を統制して判定する

最多重複（鍵の中で最も頻度の高い数字の出現回数）は3関数すべてで有意に相関して
おり，素のSpearman相関だけを見れば「エントロピーより普遍的な指標」に見える。
しかしこの読み方には**鍵ごとの基準線**という交絡が潜んでいる。

最多重複は，鍵ごとの基準線（最頻値予測器の正解率。何の学習もしなくても
出る正解率）自体と強く相関している。

| 関数 | 最多重複と基準線 | エントロピーと基準線 | 基準線と離陸率 |
| :-------- | :--------------------: | :--------------------: | :-------------------: |
| $f_{3,1}$ | $\rho=+0.85$，$p=0.000$ | $\rho=-0.64$，$p=0.002$ | $\rho=+0.67$，$p=0.001$ |
| $f_{2,2}$ | $\rho=+0.73$，$p=0.000$ | $\rho=-0.57$，$p=0.008$ | $\rho=+0.47$，$p=0.036$ |
| $f_{1,3}$ | $\rho=+0.25$，$p=0.284$ | $\rho=-0.36$，$p=0.122$ | $\rho=+0.52$，$p=0.019$ |

: 鍵の偏り指標と，鍵ごとの基準線（最頻値予測器の正解率）との相関

重複が多い鍵ほど答えの分布が偏り，基準線（$0.094$〜$0.157$ の範囲）が上がる。
離陸の判定は固定しきい値（検証正解率 $>0.5$）なので，基準線が高い鍵ほどこの
しきい値を越えやすくなり，これが「最多重複が離陸率に効く」という素の相関を
生んでいた疑いが強い。基準線を統制して相関を取り直すと，順位が入れ替わる。

| 関数 | 指標 | 素の相関 | **基準線を統制した偏相関** | 基準線超過分との相関 |
| :-------- | :------- | :--------------------: | :--------------------: | :-------------------: |
| $f_{3,1}$ | 最多重複 | $\rho=+0.64$，$p=0.003$ | $\rho=+0.18$，$p=0.459$ | $\rho=+0.52$，$p=0.019$ |
| $f_{3,1}$ | エントロピー | $\rho=-0.69$，$p=0.001$ | $\rho=-0.45$，**$p=0.047$** | $\rho=-0.61$，$p=0.004$ |
| $f_{2,2}$ | 最多重複 | $\rho=+0.52$，$p=0.019$ | $\rho=+0.29$，$p=0.209$ | $\rho=+0.46$，$p=0.042$ |
| $f_{2,2}$ | エントロピー | $\rho=-0.38$，$p=0.099$ | $\rho=-0.15$，$p=0.523$ | $\rho=-0.35$，$p=0.129$ |
| $f_{1,3}$ | 最多重複 | $\rho=+0.49$，$p=0.030$ | $\rho=+0.43$，$p=0.058$ | $\rho=+0.45$，$p=0.047$ |
| $f_{1,3}$ | エントロピー | $\rho=-0.74$，$p=0.000$ | $\rho=-0.70$，**$p=0.001$** | $\rho=-0.68$，$p=0.001$ |

: 基準線を統制した偏Spearman相関，および検証正解率の平均が基準線を超えた分との相関

**$f_{3,1}$・$f_{1,3}$ では，統制すると最多重複の方が消え，エントロピーが残る**
（$f_{3,1}$: $p=0.459$ 対 $p=0.047$。$f_{1,3}$: $p=0.058$ 対 $p=0.001$）。
素の相関だけでは「最多重複の方が普遍的」と読めてしまうが，基準線を統制すると
逆の結論になる。$f_{2,2}$ だけはどちらの指標も統制後に非有意（$p=0.523$／
$0.209$）のままで，まだ説明できていない。

### $f_{3,1}$ の離陸鍵は「1本の例外」ではなかった

C1（鍵5本）では $f_{3,1}$ で離陸した鍵は1本（エントロピー最小の「鍵27」）
だけだった。鍵20本で見ると，**5/20鍵**が部分的・完全に離陸している
（鍵27自身は2/2で全離陸，他4本は1/2か2/2）。「鍵27が特別な例外」ではなく，
似た偏りを持つ鍵なら他にもあることが確認できた。

# 方法論上の知見

今後の実験すべてに効くものだけを挙げる。

## 固定しきい値による判定は，基準線のシフトを経由した見かけの相関を生みうる

「偶然水準ではなく鍵ごとの最頻値基準線と比べる」という既存の規則は，しきい値
そのもの（今回は $>0.5$）には当てていたが，**相関分析には当てていなかった**。
鍵の偏り指標（最多重複）が基準線自体と強く相関する場合，固定しきい値を跨いだか
どうかの二値で相関を取ると，基準線のシフトが見かけの相関として現れる。
**鍵の性質と結果の関係を調べるときは，基準線を説明変数に含めた偏相関，または
基準線超過分を目的変数にした相関を併記する。**

## 予算の妥当性は，既存データの読み直しで確認できることがある

「エポック予算が十分か」を確かめるために新しいrunを増やす必要はなかった。
C1で保存済みの検証正解率の履歴（エポックごとの全履歴をJSON Linesに保存している）
を読み直すだけで，「終盤で上昇の気配があるか」を判定できた。**計算資源を使わずに
方法論上の懸念を1つ潰せた**好例である。

## モデルが小さいときはスレッド数よりプロセス数を増やす

パラメータ数が数万程度の小さいモデルでは，1プロセスに複数スレッドを割っても
CPU使用率は1.7コア程度にしか達しない。**スレッドを減らしプロセスを増やす方が
同じコア数でも速い。** ただし物理コア数を超える過剰占有（本実験では20コアに対し
30プロセス）はむしろ悪化するため，上限は「コア数まで」である。

## 実験の設計

基準線の交絡を取り除いた上で，エントロピーの効果が本当に残るかを検証する。

> **H-C2″**：鍵の偏り（エントロピー）が離陸率に効くのは，鍵ごとの基準線を
> 統制しても残る効果である（＝閾値を越えやすくなるからではなく，$x_j$ 参照
> という構造自体の学習しやすさに効く）。
>
> **予測**：基準線をほぼ揃えた鍵集合でも，エントロピーと離陸率（または基準線
> 超過分）の相関が残る。
>
> **反証条件**：基準線を揃えると相関が消える。そのとき鍵の効果の正体は基準線
> のシフトだったことになる（$f_{2,2}$ はすでにこの形）。

## 研究の枠組み

HCP（人間計算可能パスワード）とは，ユーザーが記憶する秘密の数表（以下「鍵」，各要素は0〜9の整数）と，暗算できる程度の簡単なアルゴリズムを使い，ランダムな入力（チャレンジ）から出力（レスポンス）を計算する認証方式である。本研究では，この「鍵をLLMがどこまで当てられるか／使いこなせるか」を測定するベンチマークとして再定義して扱っている。鍵と乱数シードから未知の問題を無限に生成できるため，事前学習データに答えが混入していないという利点がある。

研究は3つの経路で進めている：

1. 経路A（in-context推論）：LLMの重みは一切更新せず，プロンプトの中にいくつかの入出力example（チャレンジ→レスポンスの組）を見せて，その場で鍵を推論・逆算させる。

2. 経路B（ファインチューニング）：大量の入出力ペアを使い，追加学習（QLoRA）でLLMの重みに鍵とその使い方を覚え込ませる。従来の機械学習モデル（CNN）と同じ枠組みで，研究室の先行研究と直接比較できる。7月に一区切りとしたが，8月の指導教員の指示「より難しい関数の探索」を受けて再開している。

3. 経路C（1から学習する Transformer）：事前学習を持たない小さな Transformer エンコーダを，先行研究の CNN と同じデータ・同じ評価で学習させる。**先行研究との差分が self-attention だけになる**ため，アーキテクチャの効果だけを取り出せる。2026年9月に着手した。

## 実験の基本設定

1. **モデル**：ローカルで動かせる Qwen2.5-3B-Instruct を用い，QLoRA（4bit量子化＋LoRA）で追加学習している。

2. **Bパラダイム**：経路Bで採用している学習・評価形式。プロンプトはFew-shot例を含まない最小形式（「Input: [...] に対する Z を答えよ」のみ）とし，従来のCNNと同じ「入力→出力の直接対応のみを学習する」条件に揃えている。

3. **paradigm=pure**：教師データの形式。学習の答え（教師completion）は `{"answer": <値>}` というJSON1行のみで，計算の途中経過や鍵の値は一切含まない。損失もこの1行にしかかからず，プロンプト側（ルールの説明文を含む）には一切かからない。

4. **held-out評価**：学習に使ったデータとは別に生成した，一度も見せていない入力で正解率を測定する。学習用と評価用でチャレンジの乱数シード空間を分離しており，重複しないことを保証している。

5. **学習条件**：学習1000件・5エポックを標準としている（1000件という数は，比較対象であるCNNの学習データ量に揃えたもの）。

## 記号の定義（原論文の記法）

### 秘密写像 σ（＝本研究で「鍵」と呼んでいるもの）

$$
\sigma : [n] \to \mathbb{Z}_{10}
$$

$[n]$ は $1$ から $n$ までの自然数の集合 $\{1, 2, \dots, n\}$，$\mathbb{Z}_{10}$ は10で割った余りの同値類，すなわち1桁の整数の集合 $\{0, 1, \dots, 9\}$ である。つまり $\sigma$ は，画像や文字など n 個のオブジェクトから10進数の数字への写像であり，ユーザーはこれを暗記する。

### チャレンジ C

$$
C_i \in [n]^k
$$

$C_i$ は $i$ 番目のチャレンジ，$[n]^k$ は集合 $[n]$ の直積を $k$ 回とったもの，すなわち $[n]$ の要素を並べた長さ $k$ の列の全体である。

ここでの $k$ は「1回のチャレンジで提示するオブジェクトの個数」＝チャレンジ長であり，関数 $f$ が受け取る入力の個数と一致する（原論文は一般形を $f : \mathbb{Z}_{10}^k \to \mathbb{Z}_{10}$ と書く）。**この $k$ は，後述する関数族のパラメータ $k_1$・$k_2$ とは別のものである**。両者には $k = 10 + k_1 + k_2$ という関係がある。

### レスポンス

$$
f(\sigma(C))
$$

$\sigma(C)$ は，チャレンジ $C = (C_1, C_2, \dots, C_k)$ の各要素に秘密写像 $\sigma$ を適用したもの，すなわち $(\sigma(C_1), \sigma(C_2), \dots, \sigma(C_k))$ である。サーバは公開されたチャレンジを提示し，ユーザーは暗記した $\sigma$ で数字に直してから関数 $f$ を暗算し，その結果を答える。

## 本研究のパラメータと原論文の設定の対応

原論文で確認した内容である（2026-08）。

| | 本研究 | 原論文 |
| :--------------- | :-----------: | :------------------------------------ |
| $n$（$\sigma$ のマス数） | 10 または 26 | 説明用の例示として n=26 を挙げるが，実験・公開チャレンジの主軸は n=50・100。著者自身は n=100 を約2時間で暗記したと報告 |
| $k$（チャレンジ長） | 14 | 14（入力変数は $10+k_1+k_2$ 個。$(k_1,k_2)$ が (1,3)(2,2)(3,1) のいずれでも14で揃う） |

: 本研究のパラメータと原論文の設定の対応

プログラム中の `sgm` が $\sigma$，`X[i]` が $C_i$ にあたる。$n$ と $k$ は独立なパラメータであり，直接の関係はない。

なお原論文は n=26 を**安全性が不十分**と明示している（"the value n = 26 is too small to provide UF-RCA security even with small values of m"）。CSPソルバー攻撃（$f_{22}$）の結果は次の通りで，n=26 は全条件で破られている。

| n | m=50 | m=100 | m=1000 | m=10000 |
| :-----: | :------: | :------: | :------: | :------: |
| 26 | 23.5時間 | 40分 | 10分 | 2分 |
| 30 | HARD | UNSOLVED | 10分 | 20秒 |
| 50 | HARD | HARD | UNSOLVED | 7時間 |
| 100 | HARD | HARD | HARD | UNSOLVED |

: CSPソルバー攻撃（$f_{22}$）による鍵の復元にかかる時間

したがって本研究が n=26 や n=10 を用いる理由は「安全な設定を再現するため」ではなく，**LLMの能力を測るベンチマークとして，差が観測できる難易度水準を選んだため**である。この区別は卒論で明記する必要がある。なお $n$ を大きくすると $\sigma$ の暗記負荷が上がるため，安全性と可用性は原理的にトレードオフの関係にある。

**Stage（情報開示レベル）**：0=ヒントなし，1=$\sigma$開示・ルール非開示，2=ルール（関数 $f$）は開示するが $\sigma$ は非開示，3=ルール開示＋$\sigma$の一部を開示。本研究は主にStage 2で行っている。

このStage 2という設定は恣意的なものではなく，**原論文の攻撃者モデルと厳密に一致する**（2026-08 に確認）。原論文の Password Unforgeability game（Definition 2）には *"The adversary is given the function f … and is shown the challenges"* と明記されており，「アルゴリズムは既知，鍵のみ秘密」というケルクホフスの原理に立脚した設定になっている。つまり本研究がルールを開示して鍵だけを隠すのは，原論文の安全性証明の前提そのものである。

## 人間計算可能関数 $f_{k_1,k_2}$

原論文が提案する関数族は次の形をしている。

$$f_{k_1,k_2}(x_0, x_1, \dots, x_{9+k_1+k_2})
   = x_j + \sum_{i=10+k_1}^{9+k_1+k_2} x_i \pmod{10}
$$

$$
\text{ここで}\quad j = \left( \sum_{i=10}^{9+k_1} x_i \right) \bmod 10
$$

入力変数は $10 + k_1 + k_2$ 個＝チャレンジ長 $k$ である。入力ベクトルは $x = (\sigma(C_0), \dots, \sigma(C_{9+k_1+k_2}))$，すなわちチャレンジに $\sigma$ を適用した後の数字列である。$k_1$ 個の項を足して添字 $j$ を作り（＝どこを見るかを決める），参照した値 $x_j$ にさらに $k_2$ 個の項を足して答えとする。先頭の10個（$x_0$〜$x_9$）は動的参照の飛び先として確保される（$j$ が $\bmod 10$ で決まるため）。

本研究の主対象 `func_22` は $(k_1, k_2) = (2, 2)$ の場合にあたる。

## 安全性パラメータ $s(f)$

原論文は，攻撃者が $\sigma$ を復元するのに必要な観測数が $m = \tilde{\Omega}(n^{s(f)})$ であると示しており，その指数 $s(f)$ を次のように定義している。

$$
s(f) = \min\left\lbrace \frac{r(f)}{2},\ g(f)+1 \right\rbrace
$$

$r(f)$ は**分布的複雑度**，すなわち出力に偏り（相関）を生じさせないために固定しなければならない最小の入力変数数であり，提案関数では $r(f_{k_1,k_2}) = k_2 + 1$ である。$g(f)$ は**線形化変数数**，すなわち完全な線形方程式に退化させるために固定しなければならない最小の入力変数数であり，$g(f_{k_1,k_2}) = \min\lbrace k_1, 10\rbrace$ である。これを代入すると

$$
s(f_{k_1,k_2}) = \min\left\lbrace \frac{k_2+1}{2},\ k_1+1,\ 11 \right\rbrace
$$

となり，`func_22` では $s(f) = 1.5$ である。

この $r(f)$ の定義「出力に偏りを生じさせないために固定すべき変数数」が $k_2+1$ であることは，**最後の加算項 $k_2$ が出力分布の偏りを打ち消す役割を担っている**ことを意味する。今回の実験C2は，この構造が離陸しやすさに直接効くかを検証し，反証した（2.3節）。同時に，鍵の偏り自体が基準線を通じて評価に交絡することも分かった（2.4節）。

## 難易度の分解と，扱っている関数の定義

本命の関数 `func_22` の難しさを3要素に分解し，簡単な要素から単独で検証できるよう診断用の関数を作成している。`sgm[i]` は鍵の i 番目，`X[i]` はチャレンジの i 番目を表す。

| 名称 | 計算式 | 分離している要素 |
| :--- | :--- | :--- |
| `lookup_k` | $Z = \text{sgm}[X_0]$ | ① 記憶のみ |
| `table_add_k` | $Z = (\text{sgm}[X_0] + \text{sgm}[X_1]) \bmod 10$ | ① + ② 合成 |
| `pointer_k` | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 10$<br>$Z = \text{sgm}[X_j]$ | ① + ③ 動的参照 |
| `func_22`（本命） | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 10$<br>$Z = (\text{sgm}[X_j] + \text{sgm}[X_{12}] + \text{sgm}[X_{13}]) \bmod 10$ | ① + ② + ③ |
| `table_add3_k` | $Z = (\text{sgm}[X_0] + \text{sgm}[X_1] + \text{sgm}[X_2]) \bmod 10$ | ① + ②（静的3項．統制） |
| `narrowptr_k_m1` | $j = (\text{sgm}[X_{10}] + \text{sgm}[X_{11}]) \bmod 1 = 0$<br>$Z = (\text{sgm}[X_j] + \text{sgm}[X_{12}] + \text{sgm}[X_{13}]) \bmod 10$ | 文面は動的・実質静的（統制） |
| `func_pow` | $Z = (\text{sgm}[X_{10}]^4 + 2\,\text{sgm}[X_{11}]^3 + 3\,\text{sgm}[X_{12}]^2 + 4\,\text{sgm}[X_{13}]) \bmod 10$ | 小川さんら Table 6 の no-j 統制そのもの |

: 難易度を3要素に分解した診断用の関数

「動的参照」とは，計算の途中で求めた数値 j を使ってチャレンジの j 番目の要素を新たに読みに行き，その値をさらに鍵で変換する，という間接参照の構造を指す。

## これまでの結果の要点（今回の報告の前提）

> [!WARNING]
> **7〜8月の結論の多くは撤回・保留になっている。**原因は関数の難しさではなく
> 測定系だった（9月13日の報告）。ここには現時点で保っている結論だけを書く。

### 測定について（経路B で判明したこと）

1. **正解率が偶然水準付近でも「学習できない」とは言えない。**与えた学習予算の中で
   学習が**離陸したか**を測っていた。同じ関数・同じ鍵でもデータの引き方を変えると
   10.2% が 100% になる。
2. **1条件1run では何も言えない。**離陸は run ごとに起きるか起きないかであり，
   平均±標準偏差はその混合比を報告しているにすぎない。**離陸率**で報告する。
3. **偶然水準（10%）と比べてはいけない。**鍵ごとの**最頻値基準線**と比べる。
4. **鍵を揃えずに関数を比べてはいけない。**「$n=10$ で動的参照の有無が 100% 対 34%」
   という7月の統制実験は鍵を揃えていない比較であり，撤回した。

### 関数と難しさについて

5. ①記憶と②合成は，十分なデータ量があれば学習できる（未知の組み合わせでも汎化する）。
6. **③動的参照（$j$ 項）は，self-attention を与えると解ける。**経路C で
   $N=26$・50,000件の $f_{2,2}$ が検証 1.0000・試験 0.9998 に達した。小川さんらの CNN は
   同条件で最大 0.6858・平均 0.2872 であり，**「$j$ 項が構造的な壁」という
   先行研究の中心的結論はアーキテクチャ依存の主張に弱まる**。
7. **難しさは理論指標 $s(f)$ の順に並ばない（むしろ逆順）。**離陸率は
   $f_{3,1}$（$s=1.0$）4/20 ＜ $f_{1,3}$（$s=2.0$）11/20 ＜ $f_{2,2}$（$s=1.5$）15/20。
8. **離陸するかは，多くの場合鍵 $\sigma$ そのものの性質で決まる。**鍵5本 × 初期値4通りに
   分解すると，$f_{3,1}$ では鍵が分散の 100%，$f_{1,3}$ では 85% を説明する。
9. **崩壊点は観測密度にある。**鍵サイズを 26 → 50 にすると $f_{2,2}$ の離陸率は
   15/20 → 3/20 に落ちる（統制は 20/20 → 16/20）。データ量も 10,000件では
   $j$ 項ありが全条件 0/20 で，50,000件で初めて離陸する。
10. **鍵の効果は再現するが，$k_2$ 順に強まるという予測は反証された。**鍵20本に
    増やしても離陸率はC1（鍵5本）とほぼ一致する一方，エントロピーとの相関強度は
    $f_{1,3}$（$k_2=3$）$\approx$ $f_{3,1}$（$k_2=1$）$\gg$ $f_{2,2}$（$k_2=2$）で，
    予測した順序には並ばない（実験C2，今回の報告の主結果）。
11. **鍵の偏りが離陸率に効くかは，鍵ごとの基準線を統制して判定する必要がある。**
    鍵の最多重複（最頻値の出現回数）は，鍵ごとの基準線（最頻値予測器の正解率）
    自体と強く相関しており，固定しきい値による離陸判定だけを見ると，基準線の
    シフトを経由した見かけの相関が混ざる。基準線を統制すると，$f_{3,1}$・
    $f_{1,3}$ では**エントロピーの方が残り**，最多重複は消える（$p=0.459$／$0.058$）。
    $f_{2,2}$ はどちらの指標も統制後は非有意で，未解決である。

## 用語（本研究で独自に使っているもの）

学習一般の用語（損失・エポック・LoRA など）は
[llm_training_basics.md](../llm_training_basics.md) の用語表にある．

| 用語 | 意味 |
|---|---|
| 鍵 / $\sigma$ | 利用者が記憶する秘密の数表．長さ $n$，各要素は 0〜9 |
| チャレンジ / $C$ | 認証のたびに提示される $k$ 個の位置の並び |
| レスポンス / $Z$ | チャレンジに対して暗算で返す1桁の数字 |
| 鍵シード（`key_seed`） | どの鍵を使うかを決める乱数シード |
| データシード（`data_seed`） | どのチャレンジを引くかを決める乱数シード．鍵は変えない |
| 衝突確率 | $\sum_i p_i^2$．答えの分布を完全に知った上で独立に当てずっぽうしたときの正解率．**偶然水準（10%）ではなくこれと比べる** |
| 最頻値基準線 | 最も多い答えを常に返す戦略の正解率．計算能力ゼロでも出る下限 |
| 離陸 | 学習が動き出し，検証損失が急に落ちること．本研究では検証損失 0.15 を下回った最初のエポックで判定する |
| 床 | 正解率が偶然水準付近に張り付き，条件間の差が識別できない状態 |
| 離陸率 | 同一条件を反復したうち離陸した run の割合．**経路C の主指標** |
| 初期化シード（`init_seed`） | 重みの初期値を決める乱数シード．鍵シードと分けて振る |
| $m^*_{\text{info}}$ | 鍵が一意に定まる最小観測数．情報量の下限 |
| 動的参照 | 参照する位置そのものを計算して決めること（$X_j$ の $j$ を入力から作る） |
| 静的参照 | 参照する位置が固定されていること（$X_0$, $X_{12}$ など） |
| 最多重複 | 鍵の数字分布のうち，最も頻度の高い数字が出現する回数．エントロピーと並ぶ偏りの指標 |
| 基準線（鍵ごとの最頻値予測器の正解率） | その鍵のもとでの正解分布に対し，最も多い答えを常に返したときの正解率．学習なしで計算できる |
