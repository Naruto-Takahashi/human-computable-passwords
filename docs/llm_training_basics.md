## すべての学習に共通する骨格

事前学習だろうとファインチューニングだろうと，ニューラルネットの学習は同じ4段階の
繰り返しでしかない．

1. データを何件か取り出す（**バッチ**）
2. モデルに通して，正解とのズレを測る（**損失**）
3. 各パラメータをどちらにどれだけ動かせば損失が下がるかを計算する（**勾配**，誤差逆伝播）
4. その方向に，ある**歩幅**（学習率）で動かす

この1回を **ステップ**（イテレーション）と呼ぶ．違うのは「何をデータとするか」
「何を損失とするか」「どのパラメータを動かすか」だけである．

## LLM の学習の段階

現代の LLM は，いくつかの段階を経て作られる．**どれも上の骨格は同じ**で，
データと損失の掛け方が違う．

| 段階 | 何から始めるか | データ | 損失を掛ける場所 | 規模の目安 |
|---|---|---|---|---|
| **事前学習** | ランダムな重み | 大量のテキスト | 全トークン | 数兆〜十数兆トークン，数千GPU・数ヶ月 |
| **継続事前学習** | 学習済みモデル | 特定分野のテキスト | 全トークン | 数十億〜数千億トークン |
| **SFT（指示学習）** | 学習済みモデル | 入力と望ましい出力の組 | **出力側のみ** | 数千〜数百万件 |
| **選好学習**（RLHF / DPO） | SFT 済みモデル | 「A より B が良い」の組 | 出力側（比較） | 数万〜数十万件 |

**事前学習の目的関数は「次のトークン予測」だけ**である．文章の途中まで見せて次の
1トークンを当てさせる，を延々と繰り返す．文法も知識も推論も，すべてこの単純な
目的から副産物として生まれる．

**SFT は事前学習と同じ next-token prediction を使う．** 違うのは，
「プロンプト部分には損失を掛けず，答えの部分だけに掛ける」点だけである
（本研究の `assistant_only_loss=True`）．プロンプトを暗唱させたいのではなく，
プロンプトを与えられたときに正しく答えさせたいため．

**選好学習だけは損失の形が違う．** 「良い応答」と「悪い応答」の相対的な
好ましさを学ぶので，1つの正解に近づけるのではなく2つの差を広げる．

### 事前学習の規模感

モデルの大きさとデータ量には経験的な最適比がある（Chinchilla 則）．
おおよそ **パラメータ1個あたり20トークン**程度を学習させるのが計算効率が良い，
という結果が知られている．30億パラメータなら600億トークンが目安になる
（実際の最近のモデルはこれよりずっと多く学習させる傾向にある）．

本研究が使う Qwen2.5-3B-Instruct は，すでに事前学習と SFT と選好学習を終えた
状態で配布されている．**我々がやっているのは，その上にさらに載せる4段目**である．

## 損失 — 何を最小化しているのか

言語モデルの損失は **交差エントロピー（cross entropy）** である．

$$\mathcal{L} = -\frac{1}{N}\sum_{t=1}^{N} \ln p_\theta(x_t \mid x_{<t})$$

「正解のトークンに，モデルが何割の確率を割り当てたか」の対数を取り，符号を反転し，
トークン数で平均したもの．**正解率ではない．**

| 損失 | 意味 |
|---|---|
| 0 | 正解のトークンに確率1を割り当てている（完璧） |
| $\ln V$ | 語彙 $V$ 個から完全に当てずっぽう |

語彙が15万語なら当てずっぽうの損失は $\ln 150000 \approx 11.9$ である．
$e^{\mathcal{L}}$ を **パープレキシティ**と呼び，「実質何択で迷っているか」と読める．

### なぜ正解率ではなく損失を見るのか

**損失は連続的に動くが，正解率は飛び飛びにしか動かない．**

答えが0〜9の10択なら，正解率10%は「まったく分からない」と区別がつかない．
一方，損失は「確からしさ」を測るので，まだ正解を出せない段階でも
**改善し始めた瞬間から動く**．

本研究の実例：教師出力 `{\n  "answer": 7\n}` は9トークンで，
難しいのは数字1個だけ（残りは定型文）．したがって

| 検証損失 | 意味 |
|---|---|
| $-\ln(1/10) / 9 = 0.256$ | 数字が**まったく**分からず0〜9に一様に迷う |
| **0.19**（実測） | 定型部分と鍵の値域は覚えたが，答えは当てられない＝**学習が始まっていない** |
| 0.0005（実測） | 正解の数字に約99.6%の確率を割り当てている |

正解率では「10%」も「12%」も偶然と区別できないが，損失を見れば
「学習の途中」か「一歩も動いていない」かが分かる（[measurement_audit.md](measurement_audit.md)）．

## 最適化 — どうやって下るのか

### 勾配降下

損失を各パラメータで偏微分すると「どちらに動かせば損失が下がるか」が分かる．
その方向に歩幅 $\eta$（学習率）だけ動かす．

$$\theta \leftarrow \theta - \eta \nabla_\theta \mathcal{L}$$

### 最適化アルゴリズム

| 手法 | 特徴 |
|---|---|
| SGD | 勾配をそのまま使う．単純だが学習率の調整が難しい |
| Momentum | 過去の勾配を慣性として持つ．振動を抑える |
| **Adam** | パラメータごとに歩幅を自動調整する．勾配の1次モーメント（平均）と2次モーメント（分散）を保持 |
| **AdamW** | Adam の重み減衰を分離して正しく扱う版．**現在の LLM 学習の事実上の標準** |

Adam 系は**パラメータ1個につき2つの状態**（$m$, $v$）を持つ．これがメモリを食う
（後述）．

### 学習率スケジュール

学習率は普通，最初から最後まで一定にはしない．

- **Warmup**: 最初の数%で 0 から目標値まで上げる．Adam の2次モーメントは序盤の
  推定が当てにならず，いきなり大きく動かすと壊れやすいため．**多くの学習レシピで
  標準的**（3〜10%程度）
- **減衰**: その後 0 に向けて下げる．線形・コサインなどがある．最初は大股で
  大まかな谷へ，最後は小股で谷底に落ち着かせる狙い

**重要な性質**: 減衰は「全ステップ数」を基準に計算される．したがって
**エポック数を変えると学習率の下がり方まで変わる**．エポック数は単なる
繰り返し回数ではなく，予算の宣言でもある．

### 勾配クリッピング

勾配が大きくなりすぎたときに上限で頭打ちにする（本研究は `max_grad_norm=1.0`，
HuggingFace の既定値）．稀に現れる異常な勾配で学習が壊れるのを防ぐ．

## バッチ・ステップ・エポック

- **バッチ**: 1ステップで見るデータ件数．大きいほど勾配が安定するがメモリを食う
- **ステップ**: 重みを1回更新すること
- **エポック**: 訓練データ全体を1周すること

$$\text{ステップ数} = \frac{\text{データ件数}}{\text{バッチサイズ}} \times \text{エポック数}$$

**勾配蓄積（gradient accumulation）** は，メモリ不足のときに使う仕掛けである．
たとえばバッチ8を一度に流せないなら，2件ずつ4回forwardして勾配を足し，
それから1回だけ更新する．**数学的にはバッチ8と同じ**で，時間と引き換えに
メモリを節約する．

$$\text{実効バッチ} = \text{バッチサイズ} \times \text{勾配蓄積ステップ数}$$

なお **事前学習ではエポックという概念をあまり使わない**．データが膨大なので
全体を1周すらしないことが多く，「何トークン学習したか」で数える．
エポックが意味を持つのは，データが有限で何周もする追加学習の側である．

## 汎化と過学習

学習の目的は「訓練データで正解すること」ではなく「**見たことのないデータで
正解すること**」である．これを**汎化**という．

そのためデータを3つに分ける．

| 分割 | 用途 | 重みを更新するか |
|---|---|---|
| 訓練（train） | 重みを動かす | する |
| 検証（validation） | 学習中の様子を見る・ハイパーパラメータを選ぶ | **しない** |
| テスト（test） | 最終評価 | しない |

検証データで「選ぶ」ことをすると，検証データにも間接的に適合してしまう．
だから最終評価は，選択にも使っていないテストデータで行う．

**過学習（overfitting）** は，訓練データの細かい癖まで覚えてしまい，
未知のデータで性能が落ちる現象．典型的には次のように現れる．

```
訓練損失: ↓↓↓↓↓   （下がり続ける）
検証損失: ↓↓↑↑↑   （途中から上がる）  ← ここが過学習の始まり
```

4つの状態が読める．

| 訓練損失 | 検証損失 | 状態 |
|---|---|---|
| 高い | 高い | **まだ学習が始まっていない**（未学習） |
| 下がる | 下がる | 順調に汎化している |
| 下がる | 上がる | **過学習** |
| 低い | 高いまま → 突然落ちる | **grokking**（遅延汎化） |

**grokking** は，訓練データを丸暗記した後もずっと汎化しないままでいて，
さらに長く学習を続けると突然汎化する現象．mod $p$ の四則演算のような
規則的な課題で最初に報告された．

## 正則化

過学習を抑える手立てを総称して正則化という．

**ドロップアウト**: 学習中，ニューロンの一部をランダムに 0 にする．

```
入力 x = [0.8, 0.3, 0.5, 0.9, 0.2, ...]
         ↓ ドロップアウト率 5%
      = [0.8, 0.0, 0.5, 0.9, 0.2, ...]
                ↑ このステップでは捨てる（残りは 1/(1-0.05) 倍に拡大）
```

どれを捨てるかは毎ステップ引き直す．**評価時は無効**になり全部使われる．
特定のニューロンに依存させないことで役割を分散させ，丸暗記を妨げる．

**重み減衰（weight decay）**: 重みが大きくなりすぎないよう，損失に
$\lambda \|\theta\|^2$ を足す（AdamW では更新式側で扱う）．

**早期終了（early stopping）**: 検証損失が上がり始めたら学習を止める．

**データ拡張**: 入力に変形を加えて実質的なデータ量を増やす．

## 数値精度とメモリ

LLM の学習で最も厳しい制約はメモリである．何が場所を取るのかを知っておくと，
手法の選択が理解できる．

| 表現 | 1パラメータあたり | 備考 |
|---|---|---|
| fp32 | 4バイト | 昔の標準 |
| fp16 / **bf16** | 2バイト | 現在の標準．bf16 は指数部が広く学習が安定 |
| int8 | 1バイト | 主に推論用 |
| **4bit** | 0.5バイト | QLoRA が使う．凍結した重みの置き場に |

学習中にメモリを占めるのは，重みだけではない．

1. **重み** 本体
2. **勾配**（重みと同じ数だけ）
3. **オプティマイザの状態**（Adam なら1パラメータにつき2つ，精度を保つため fp32）
4. **活性値**（誤差逆伝播のために順伝播の途中結果を保持．バッチと系列長に比例）

Qwen2.5-3B（31.2億パラメータ）をフル学習する場合の実測に基づく見積り：

| | 容量 |
|---|---|
| 重み（bf16） | 5.8 GB |
| 勾配（bf16） | 5.8 GB |
| Adam の状態（fp32 × 2） | 23.2 GB |
| **合計（活性値を除く）** | **34.8 GB** |

研究室の GPU は 8GB なので**まったく載らない**．ここから PEFT の話につながる．

## パラメータ効率的な学習（PEFT）

全パラメータを更新する代わりに，**ごく一部だけを学習する**手法の総称．

| 手法 | 考え方 |
|---|---|
| **LoRA** | 重みへの差分を低ランク行列の積で表し，それだけ学習する |
| Adapter | 層の間に小さなモジュールを挿入し，そこだけ学習する |
| Prefix / Prompt tuning | 入力側に学習可能なベクトルを足す |
| BitFit | バイアス項だけ学習する |

### LoRA

元の重み $W$ を凍結し，差分を2つの細長い行列の積で近似する．

$$W_{\text{使う重み}} = \underbrace{W}_{\text{凍結}} + \underbrace{BA}_{\text{学習する}} \times \frac{\alpha}{r}$$

- $A$ は $r \times d$ で**ランダム初期化**
- $B$ は $d \times r$ で**ゼロ初期化**
- $r$ は**ランク**．小さいほど学習パラメータが減る
- $\alpha$ はスケーリング．$\alpha = 2r$ とするのが慣例

$B = 0$ なので**学習開始時の出力は元のモデルと完全に同一**である．
そこから差分が育っていく．

発想の背景は「ファインチューニングで必要な重みの変化は，本質的に低い次元しか
持たない」という仮説である．

**QLoRA** は，これに4bit量子化を組み合わせたもの．凍結した重みは更新しないので，
圧縮したまま置いておける．

本研究での実測：

| | 容量 |
|---|---|
| 重み（4bit・凍結） | 1.5 GB |
| 勾配（LoRA 分のみ） | 0.1 GB |
| Adam の状態（LoRA 分のみ） | 0.2 GB |
| **合計（活性値を除く）** | **1.7 GB** |

**34.8 GB → 1.7 GB**．学習するのは全体の **0.96%**（2,993万パラメータ，実測）で，
保存されるアダプタは **69MB**（元モデルは 5.8GB）．評価時は「元モデル＋アダプタ」を
重ねて使う．

## 乱数と再現性

学習は決定的な手続きではない．乱数は主に3箇所に効く．

1. **重みの初期化** — 事前学習では全パラメータ，LoRA では $A$
2. **データの並び順** — 毎エポックのシャッフル
3. **ドロップアウト** — 毎ステップ「どれを落とすか」

これらは**シードで固定できる**．ただし固定しても**完全には再現しない**．
GPU 側に非決定性が残るためである．

- 並列に足し算する順序が実行ごとに変わる（`atomicAdd` の到着順）
- 行列積のアルゴリズムがその場で選ばれる（cuBLAS）
- 低精度（bf16・4bit）では，順序の違いが数値差として残りやすい

浮動小数点では $(a+b)+c \neq a+(b+c)$ である．完全再現が要るなら
`full_determinism=True` のような設定があるが，大幅に遅くなる．

**シード値に意味は無い．** よく見る `42` は『銀河ヒッチハイク・ガイド』の
ジョーク由来で，ライブラリの既定値として広く使われているだけの慣習である．

### 実例（本研究，2026-09-12）

`key_seed` / `data_seed` / 学習シードがすべて同一の2本で，離陸が1エポックずれた．

| | ep1 | ep2 | ep3 | ep4 | ep5 | 正解率 |
|---|---|---|---|---|---|---|
| 1本目 | 0.1835 | **0.0393** | 0.0012 | 0.0006 | 0.0006 | 100.0% |
| 2本目 | 0.1917 | 0.1549 | **0.0310** | 0.0038 | 0.0024 | 99.0% |

残る違いは GPU の非決定性だけである．最終的には両方収束するので正解率は
ほぼ同じだが，**固定エポックで打ち切る設計では，この1エポックのずれが
結果を左右しうる**．

### 1回の実行で結論を出してはいけない

学習には当たり外れがある．**同じ条件で複数シード回し，平均と標準偏差で
報告するのが研究として標準的**である．先行研究（小川ら2025）も同種の課題で
「平均 0.2872 ± 標準偏差 0.1651」と，ばらつきの大きさを報告している．

## 本研究の設定

上の枠組みの中で，本研究がどこに位置するか．

**段階**: 配布されている Qwen2.5-3B-Instruct（事前学習＋SFT＋選好学習済み）の上に，
さらに SFT を1段重ねている．

| 項目 | 値 | 一般的な水準か |
|---|---|---|
| ベースモデル | Qwen2.5-3B-Instruct | — |
| 量子化 | 4bit（QLoRA） | 標準（8GB VRAM 前提） |
| LoRA ランク $r$ / $\alpha$ | 16 / 32 | 標準（$\alpha = 2r$ が慣例） |
| 差分を入れる場所 | `q,k,v,o,gate,up,down` の全層 | 標準 |
| `lora_dropout` | 0.05 | 標準 |
| 学習対象 | 全体の 0.96%（2,993万） | — |
| 学習率 | 2e-4 | QLoRA 論文の標準値 |
| スケジュール | 線形減衰・**warmup なし** | **慣習から外れる**（通常は3〜10%の warmup） |
| optimizer | AdamW 8bit | 標準 |
| `max_grad_norm` / `weight_decay` | 1.0 / 0.0 | HuggingFace の既定値 |
| 実効バッチ | 2 × 4 = 8 | 標準（小VRAM） |
| 学習件数 / エポック | 1000 / 5（＝625ステップ） | — |
| 損失 | 答えの部分のみ | 標準 |
| 学習シード | 42（暗黙・変更する引数が無い） | **1条件1run は研究の主張としては標準的でない** |
| 所要 | 1本あたり約100分（実測） | — |

**手法の選択そのものは教科書どおりで，問題は無い．** 問題は用途である．
本研究は FT でモデルを作るのではなく，**FT を物差しにして関数の難しさを測る**．
測定器として使うなら，標準的なレシピでは足りない．

| モデルを作るなら | 難しさを測るなら |
|---|---|
| 1回学習すればよい | 複数シードで分布を取る |
| 固定エポックで打ち切ってよい | 収束まで回す（または収束を判定する） |
| 非決定性は許容 | 完全決定モードを検討する（遅くなる） |

## 用語

| 用語 | 意味 |
|---|---|
| 事前学習 | ランダムな重みから，大量のテキストで次トークン予測を学ぶ段階 |
| 継続事前学習 | 学習済みモデルに，特定分野のテキストを追加で学ばせること |
| SFT | 入力と望ましい出力の組を見せる教師ありファインチューニング |
| 選好学習 | 「A より B が良い」という比較から学ぶ段階（RLHF・DPO など） |
| 損失 | 正解にどれだけ高い確率を割り当てたかの指標．小さいほど良い |
| 交差エントロピー | 言語モデルで使う標準的な損失 |
| パープレキシティ | $e^{\text{損失}}$．実質何択で迷っているか |
| 勾配 | 各パラメータをどちらに動かせば損失が下がるかを示すベクトル |
| 誤差逆伝播 | 勾配を出力側から入力側へ連鎖律で計算する手続き |
| 学習率 | 1ステップで動かす歩幅 |
| Warmup | 学習率を最初にゆっくり上げる区間 |
| ステップ | 重みを1回更新すること |
| エポック | 訓練データ全体を1周すること |
| バッチ | 1ステップで見るデータ件数 |
| 勾配蓄積 | 分割して勾配を足し，まとめて更新する省メモリの仕掛け |
| 汎化 | 見たことのないデータで正しく答えられること |
| 過学習 | 訓練データの癖を覚えて，未知のデータで性能が落ちること |
| grokking | 丸暗記の後に，さらに学習を続けると突然汎化する現象 |
| 正則化 | 過学習を抑える手立ての総称 |
| ドロップアウト | ニューロンをランダムに落とす正則化 |
| 重み減衰 | 重みが大きくなりすぎないようにする正則化 |
| bf16 | 指数部の広い16bit浮動小数点．学習で標準的 |
| 量子化 | 重みを低い精度で表してメモリを減らすこと |
| PEFT | 一部のパラメータだけ学習する手法の総称 |
| LoRA | 重みの差分を低ランク行列の積で表して学習する手法 |
| ランク $r$ | LoRA の差分行列の細さ |
| アダプタ | 学習された LoRA の重み．本研究では 69MB |
| QLoRA | 4bit量子化した凍結モデル＋LoRA |
