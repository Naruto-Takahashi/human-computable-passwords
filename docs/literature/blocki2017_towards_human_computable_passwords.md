# Blocki, Blum, Datta, Vempala "Towards Human Computable Passwords" (ITCS 2017 / arXiv:1404.0024v4)

本研究が対象とするHCP方式そのものを提案した原論文。読解日: 2026年8月。

## 1. 問題設定

ユーザーは多数のオンラインアカウントを持つが，パスワードを覚えきれず使い回しや弱いパスワードに走る。本論文が目指すのは，**多数回の漏洩後も安全性が保たれる**「人間計算可能なパスワード管理方式」である（先行のBlocki et al. / Blum-Vempalaの方式は数回の漏洩までしか耐えられなかった）。

**「半信頼コンピュータ」モデル**: 計算と保存は正しく行うが，秘密は守らない（画面の内容は攻撃者にも見える）計算機の補助を受ける前提。したがって：
- **チャレンジ** $C \in [n]^k$ は公開メモリに置いてよい（攻撃者に見えてよい）。
- **秘密写像** $\sigma: [n] \to \mathbb{Z}_d$ だけがユーザーの頭の中（連想記憶）にある。

認証は，公開チャレンジ $C$ に対して $f(\sigma(C))$ を暗算して答えるチャレンジ・レスポンス方式。パスワードは $\lambda$ 個の1桁チャレンジへの応答を連結して作る。

## 2. 提案する関数族 $f_{k_1,k_2}$

代表例（本研究の `func_22` に対応）:

$$f(x_0,\dots,x_{13}) = x_{13} + x_{12} + x_{(x_{10}+x_{11} \bmod 10)} \bmod 10$$

一般形は，$k_1$ 項の和でポインタ $j$ を作り，参照した値 $x_j$ に $k_2$ 項を足す：

$$j = \sum_{i=10}^{9+k_1} x_i \bmod 10, \qquad f_{k_1,k_2} = x_j + \sum_{i=10+k_1}^{9+k_1+k_2} x_i \bmod 10$$

論文が評価するのは $(k_1,k_2) = (1,3), (2,2), (3,1)$ の3つで，いずれも入力長は14。

## 3. 「人間計算可能」の定式化（可用性）

人間の計算を**空間制約付きストリーミングアルゴリズム**としてモデル化する点が特徴的。

- **原始操作** $P$ = {`Add`（2桁のmod 10加算）, `Recall`（記憶した $\sigma(i)$ の想起）, `TableLookup`（10個の添字表からの参照）}。
- **Definition 2**: 関数 $f$ が $(P,\tilde{t},\hat{m})$-computable ⟺ $P$ の操作を $\tilde{t}$ 回だけ使い，作業記憶 $\hat{m}$ スロットで計算するストリーミングアルゴリズムが存在する。作業記憶は人間の短期記憶の制約から $\hat{m}=3$ 程度を想定し，中間結果の長期記憶への書き込み（`MemorizeValue`）は禁止する。
- **Fact 1**: $f_{k_1,k_2} \circ \sigma$ は $(P, 2k_1+2k_2+1, 3)$-computable。
- 著者自身が $f_{1,3}$・$f_{2,2}$ を **7.5秒**で計算できたと報告。$n=100$ の写像 $\sigma$ の記憶には約2時間かかったとある。

> **本研究との関連**: 鍵サイズ $n=26$ は「26文字のアルファベットから数字への写像を覚える」という論文自身の例示（"if n = 26 and d = 10 then the user might memorize a random mapping from characters to digits"）に由来する。

## 4. 安全性の定式化

### 4.1 攻撃ゲーム（Password Unforgeability, §2.3）

**この定義が本研究のStage 2設計の直接的な根拠である。**

> The adversary is given the function $f : \mathbb{Z}_d^k \to \mathbb{Z}_d$ and is shown the challenges $C_1,\dots,C_{m+\lambda}$ as well as the values $f(\sigma(C_i))$ for $i \in \{1,\dots,m\}$.

つまり原論文の攻撃者モデルは，**「関数 $f$（＝計算規則）は攻撃者に最初から与える。秘密写像 $\sigma$（＝鍵）だけを隠す」**という設定である。これはケルクホフスの原理そのものであり，本研究の Stage 2（ルール開示・鍵非開示）が恣意的な条件設定ではないことを保証する。

**Definition 3 (UF-RCA security)**: 任意の確率的多項式時間攻撃者 $A$ に対し，$\Pr[\text{Wins}] \le \delta$ であるとき $f$ は $UF\text{-}RCA(n,m,\lambda,\delta)$-secure。

### 4.2 安全性パラメータ $s(f)$（Claim 1）

$$s(f_{k_1,k_2}) = \min\left\{\frac{k_2+1}{2},\ k_1+1\right\}$$

| 関数 | $k_1$ | $k_2$ | $s(f)$ |
|---|---|---|---|
| $f_{1,3}$ | 1 | 3 | 2.0 |
| $f_{2,2}$ | 2 | 2 | 1.5 |
| $f_{3,1}$ | 3 | 1 | 1.0 |

統計的攻撃者が $\sigma$ を復元するには $m = \tilde{\Omega}(n^{s(f)})$ 組のチャレンジ・レスポンスの観測を要する。証明は，$f$ と $\sigma$ が誘導する分布の**統計的次元 (statistical dimension)** を，一般ハイパーコントラクティビティ定理を用いて下から抑えることによる（Feldman et al. の $d=2$ の結果を一般の $d$ に拡張）。

**$r(f) = k_2+1$ の直観**: $k_2$ 個の変数を固定しても出力を偏らせられない（和 $x_j + \sum x_i$ の中に必ず未固定の変数が1つ残るので出力は一様に $1/10$）。逆に $k_2+1$ 個を固定すれば偏らせられる。

> **本研究との関連**: この「最後の加算項 $k_2$ が安全性を担う」という構造は，2026年8月に発見した**「足し算のない関数（$k_2=0$）では鍵の数字ヒストグラムがそのままレスポンス分布に漏れる」**という現象の理論的裏付けになっている（`plan.md` §3.1.1）。$k_2=0$ は $s(f)=0.5$ に相当し，原論文の安全性の枠外にある。

### 4.3 ソルバーによる実証的攻撃（§3.2.1）

Microsoft Solver Foundations のCSPソルバーで実際に $\sigma$ 復元を試行（2.5日の計算時間）。**復元に失敗した**のは以下：$f_{2,2}, f_{1,3}$ について (1) $n=30, m=100$，(2) $n=50, m=1000$，(3) $n=100, m=10000$。

**Remark 2 が重要**: 理論上の $s(f_{1,3})=2.0 > s(f_{2,2})=1.5$ にもかかわらず，**小さい $n$（$n \le 100$）では $f_{2,2}$ の方が安全と予想**している。$f_{1,3}$ にはガウス消去に基づく多項式時間攻撃があり $n^2$ 個の例で $\sigma$ を復元できるのに対し，$f_{2,2}$ では同じ攻撃に $n^3$ 個必要なため。

なお論文は $n=26$ について，SATソルバーによる攻撃実験の結果から「$n=26$ は小さすぎてUF-RCA安全性を提供しない」と明示的に注意している。

## 5. 本研究における位置づけ

1. **Stage 2 設計の正当化**: §4.1 の Definition により，「規則を開示して鍵だけ隠す」という本研究のFT実験設定は原論文の脅威モデルと厳密に一致する。
2. **関数族の対応**: 本研究の `func_13`/`func_22`/`func_31` は原論文の $f_{1,3}/f_{2,2}/f_{3,1}$ に直接対応する。
3. **$k_2$ の意味の理解**: $s(f)$ の式が $k_2$ を報酬することは，本研究が診断用に作った「足し算を省いた」関数（`pointer_k`, `pointer_chain`）が構造的に脆弱（鍵の偏りが漏れる）である理由を説明する。
4. **限界の認識**: 原論文自身が $n=26$ を「安全性が不十分」と認めているため，本研究が $n=26$ を使うのは「安全な設定の再現」ではなく「学習可能性を測るベンチマークとしての難易度水準の設定」と位置づけるべきである。
