# 推論時の計算と思考過程

> なぜ LLM は「計算」できるのか。Chain of Thought は何をしているのか。
> 思考過程はどこまで信用できるのか
>
> 📚 [ドキュメント索引](README.md) ／ 関連: [学習の基礎](llm_training_basics.md) ・
> [測定系の監査](measurement_audit.md)

**学習の話は [llm_training_basics.md](llm_training_basics.md) にある。**こちらは
**学習が終わったあと，推論の時に何が起きているか**を扱う。経路A（プロンプティング）で
「計算ツールを使わせない」「思考過程を採点しない」という設計判断の根拠になる。

## 次トークン予測と，計算能力の獲得

**「次のトークンを予測する」は学習の目的であって，中で何をしているかの説明ではない。**

`3 + 4 = ` の次に `7` を高い確率で出すには，加算を実装するのが最も安上がりである。
暗記表より汎化するので損失が下がる。**予測のために計算を獲得する**という関係にある。

実際，小さい Transformer に剰余加算を学習させると，内部にフーリエ変換に似た
回路ができることが解析で示されている。表引きではなく計算している。

ただし**学習された近似**であって厳密な算術器ではない。桁が増えると崩れ，
長い連鎖ではずれる。

## 1回の順伝播でできることは有限

$`L`$ 層のモデルは，おおむね $`L`$ 段の逐次処理しか持てない。

| | できる | できない |
|---|---|---|
| 1回の順伝播 | 深さが固定された計算。数ステップの算術 | **ループ**（収束するまで繰り返す） |

「試して，矛盾したら戻る」という探索は，1回の順伝播では実行できない。

## Chain of Thought は逐次計算を稼ぐ仕組み

生成したトークンが入力に戻るので，文脈が作業メモになる。

```
1回の順伝播 = 深さ L の固定回路
CoT        = それを何百回も連ねた逐次機械
```

理論的にも，CoT を許すと表現できる計算のクラスが広がることが示されている。

**飾りではない。**CoT を取り上げると多段の課題で性能が落ちる。さらに示唆的なのは，
意味を持たない詰め物トークンでも一定の効果が出る場合があると報告されていることで，
**「考えを書いている」というより「計算の段数を稼いでいる」**側面が確かにある。

### 書き足しであって，繰り返しではない

同じものを反復精錬するのではなく，**末尾に追記していく**。前に書いたものは消せない。

だから推論モデルの思考過程には「いや待て，これは違う」という書き直しが
**文字として現れる**。訂正する唯一の方法が，訂正を書き足すことだからである。

## 推論モデルは何が違うのか

**仕組みは同じ自己回帰である。**出力を入力に戻すのは，あらゆる LLM がやっている。

違うのは**訓練**の方で，「答える前に長い思考を書き，最終的な正解で報酬を受ける」
という振る舞いを強化学習で身につけている。場所は前からあった。使い方を覚えた。

## 思考過程はどこまで信用できるか

> [!IMPORTANT]
> **計算の基盤としては本物。自己申告としては信用できない。**
> この2つは両立する。

### 両方向の食い違いが起こる

| | 起こるか | 例 |
|---|---|---|
| 思考は誤り，答えは正解 | **起こる** | 途中で計算を誤っているのに答えは合う。答えは書いた手順から出ていない |
| 思考は正しい，答えは誤り | **起こる** | 正しく導出したのに最後で違う値を書く |

もっともらしい推論を書きながら，実際の答えは別の要因で決まっていることが
観察されている（プロンプトに偏りを仕込むと，偏りに従いつつ，思考過程では
それに触れない説明を書く，など）。

### ただし，信用度には原理的な傾きがある

**書く必要が本当にある課題ほど，思考過程は本物に近づく。**

| 課題 | 思考過程の役割 |
|---|---|
| 1回の順伝播で解ける | **飾りになりやすい。**答えは既に決まっていて説明が後付け |
| **1回では解けない多段の演繹** | **本物になりやすい。**書かないと計算できない |

飾りで済むなら飾りになるし，済まないなら実際に使われる。

**本研究の課題（鍵 $`n`$ マスの制約充足）は後者である。**1回の順伝播では届かないので，
一般的な場面より思考過程が信用できる側にある。

## 本研究での扱い

### 読むのは仮説を作るため。証拠にするのは出力

| 使い方 | 可否 |
|---|---|
| 仮説を作る | ✅ 「順列だと思っているのでは？」→ 明示して測り直す |
| どこで詰まるかの当たりをつける | ✅ |
| 「制約伝播をしている」と断定する | ❌ 過大解釈 |
| 正しい推論ステップ数を指標にする | ❌ 採点できない |
| **出力そのもの**を証拠にする | ✅ **これが硬い** |

2026-09-23 に観測した「モデルの答えが 0〜9 の順列になっていた」は，
**思考過程ではなく出力の形**から分かったことなので証拠として使える
（[log.md](log.md)）。

### 「本当に使っているか」は壊して測る

思考過程を読むのではなく，操作して効果を見る。すべて出力の変化として測れる。

| 操作 | 答えが変われば | 変わらなければ |
|---|---|---|
| 思考の途中を書き換える | 本当に使っている | 飾りだった |
| 思考を途中で打ち切る | 長さが効いている | 使っていない |
| CoT を禁じる | 書く場所が必要だった | 不要だった |

本研究の課題は「使っているはず」と予測できるので，**予測が外れたらそれ自体が発見**に
なる。多段の演繹が要るはずの課題で思考過程が答えに影響しないなら，
モデルは演繹していないことになる。

### 計算ツールを禁じる理由

経路A ではコード実行を許さない。**許すと全モデルが解けて指標が機能しなくなる**
（ソルバーを書けば1秒で解ける）。

これは空虚な制約ではない。**CoT という内部の計算資源は使わせた上で，
外部の正確な計算機を禁じている。**測定しているのは
「攻撃者としての能力」ではなく「外部計算を用いない演繹能力」である。

先行研究（MLP・LSTM・CNN）もツールを持たないので，系譜とも整合する。
