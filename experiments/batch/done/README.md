## `_common.sh` を使っていない理由

2026-09-12 に `_common.sh`（学習→評価の共通手順）を作ったが，これらは
書き換えていない．理由は2つ．

1. **実行済みのスクリプトは二度と変更しない．** 重複の実害は「条件を変えるときに
   何箇所も直す」ことだが，走り終えた実験の条件は変えない．重複を消しても得がない．
2. **共通層が太る．** これらは均質ではない．`--exclude_pairs` を使うもの，
   `pure` と `rationale` を混ぜるもの，学習せず評価だけするもの，評価件数が
   50件だった頃のものが混在する．すべてを1つのAPIに通すには，今後使わない
   機能を `_common.sh` に足すことになり，共通層が読みにくくなる．

新しく書くものは `_common.sh` を使う（雛形は1つ上の README）．

## 当時と現在で違う点

- **評価件数**: 6本（`run_control_table_add3` / `run_depth_ladder_step1` /
  `step1b` / `step2` / `run_pointer_ladder` / `run_stage3` / `run_stage3b`）は
  `--n_test 50` である．50件では点推定が最大13ポイントずれ，実際に結論を誤らせた
  （2026-08）。現在の標準は500件．
- **評価結果の保存先**: 当時のパスにはアルゴリズムが先頭に無く，`n_test` も
  入っていなかった．既存結果は移行済みで，現在の構造は
  [results/README.md](../../../results/README.md) を参照．
